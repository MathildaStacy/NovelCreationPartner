1. 页面功能

  • 编辑一章正文（纯文本，按段落排版，段首缩进两字），停止输入 2 秒自动保存，离开或切到后台时立即保存。
  • 显示章节类型与状态、字数、保存状态；本章有未处理冲突时在顶部提示。
  • 撤销、重做（本次打开期间，最多 100 步，AI 插入也算一步）。
  • 召唤 AI：在光标处用描写助手生成描写；选中文字后改写、扩写、缩写、润色、补细节或按描写要求重写。
  • 不离开编辑器速查档案。
  • 定稿本章（只对正文章节）。
  • 重新进入时回到上次的光标位置；从审核、冲突、条目详情"跳到原文"时选中原句。
  • 离开时自动存一个版本快照，可在版本历史中找回。

4. 数据与本地服务

进入页面（并行）

  • chapters.get(chapterId)：标题、类型、编号、状态、字数、正文、lastCursor。正文转成显示文本后放入编辑框（5.1）。
  • conflicts.forChapter(chapterId)：决定冲突提示条，记下冲突 ID 列表。
  • prefs.get('editorFont')、prefs.get('editorFontSize')。
  • 正文加载后：有 locate 参数按 5.7 定位，否则按 5.6 恢复光标。

订阅事件

  • chapter.saved（chapterId 为本章）：用载荷中的 charCount、state 更新状态行。不重新读取正文。
  • chapters.changed：重新调用 chapters.get，只更新标题、类型、编号、状态（例如在 S06a 中改了标题或类型），保留内存中的正文和光标。
  • conflicts.changed：重新调用 conflicts.forChapter，提示条随之出现、更新或消失（例如后台冲突检测完成）。
  • prefs.changed：立即应用新的字体、字号，光标位置不变。
  • 系统 AppState 变为 background（iOS 还包括 inactive）：立即保存（立即保存）。

5. 业务规则

5.1 正文格式与段首缩进

结论：存储为纯文本，不存缩进；显示时在每段前加两个全角空格（U+3000 × 2）作为缩进字符。React Native 的 TextInput 不支持段首缩进样式（没有 textIndent），用样式做不到，所以缩进是编辑框里真实存在、但不进数据库的字符。

  1. 存储格式：段落之间用一个 \n 分隔；每段段首没有任何空白（半角空格、全角空格、制表符）；允许空段（作者用空行分隔场景）；段中和段尾的空白原样保留；\r\n、\r 统一为 \n。
  2. 显示格式：每一段（含空段）前加"　　"。由纯函数模块 editor/indent.ts 负责，需有单元测试：
    • toDisplay(body)：按 \n 拆段，每段前加两个全角空格。
    • toBody(display)：按 \n 拆段，去掉每段段首所有空白。
    • toDisplayOffset(body, offset) = offset + 2 × （offset 所在段的序号，从 1 起）。
    • toBodyOffset(display, offset) = offset − 2 × 段序号；落在缩进内的偏移取该段段首。
  3. 对外一律用存储偏移：lastCursor、AI 的 range、applyAiText 的 start/end、审核原句的 evidenceOffset、定位参数 offset 都是存储正文中的字符位置。只有和 TextInput 交互（selection、onSelectionChange）时才换算。
  4. 编辑行为（每次 onChangeText 后：body = toBody(新显示文本)，若 toDisplay(body) 与编辑框内容不同，就把编辑框回写为规范文本并换算光标）：
    • 回车：新段自动带缩进，光标在缩进之后。
    • 光标在段首（缩进之后）按删除键：与上一段合并（删去换行和本段缩进）。判断方法：这次删除只删掉了缩进里的字符、存储正文没有变化。第一段段首按删除键无效果。
    • 点按或拖选使光标、选区端点落在缩进内：吸附到缩进之后。
    • 在段首输入空格、粘贴带缩进或段首空格的文本：段首空白被去掉，统一为两个全角空格。段中输入的空格保留。
    只有上述情况才回写编辑框；普通输入不回写，避免整段重绘。
  5. 复制：系统复制取的是编辑框里的显示文本，所以复制出去带缩进（选区从段首开始时每段带两个全角空格；从段中开始时第一段不带），粘贴到网文平台或文档里直接符合排版习惯。剪切同理；本 App 内粘贴回来时按上一条规范化。
  6. 字数：缩进不计入字数——缩进不存储，且 countChars 本身不计空白（含全角空格）。"已选 N 字"同样按存储正文计算。
  7. 性能：使用受控 TextInput。验收条件：2 万字正文在中低端 Android 机上连续输入无明显卡顿（单次按键到显示 < 50 ms，UI 规范 8.2）。达不到时改为非受控，只在需要规范化时回写。

5.2 自动保存与保存状态

  1. 正文每次变化重置 2 秒计时；计时到点调用 saveBody。连续输入不停时，距上次成功保存满 10 秒也强制保存一次。
  2. 同一时间只有一个保存请求。请求进行中又有新修改时，等它完成后再按计时规则保存最新内容。每次保存带递增序号，只有最新一次成功才显示"已保存"。
  3. 保存状态：没有未保存修改 → "已保存"；从第一次修改到写入完成 → "保存中…"；最近一次写入失败 → "保存失败 · 重试"。
  4. 保存时同时写入光标位置（选中文字时取选区起点）。
  5. 撤销、重做、AI 插入后的撤销都按普通修改处理，走同样的自动保存。

5.3 撤销与重做

  1. 撤销栈和重做栈只在内存中；进入编辑器时为空，离开编辑器（页面卸载）时清空，恢复历史版本后清空。最多 100 步，超出丢弃最早的一步。
  2. 每一步记录 { start, removed, inserted, selBefore, selAfter }（存储偏移），不保存整篇正文。
  3. 合并：同一类型（都是输入或都是删除）、位置相连、与上次修改间隔 < 1 秒的修改合并为一步。以下情况开始新的一步：间隔 ≥ 1 秒、输入与删除切换、光标被移到别处、回车、粘贴或剪切、一次替换选区。
  4. AI 插入或替换单独算一步（类型 ai）。撤销后正文回到插入前，选区恢复为原来的选区；数据库里的 before_ai 快照保留不删。
  5. 新的修改清空重做栈。段首缩进规范化引起的变化并入触发它的那一步。
  6. 撤销、重做后滚动到改动处；键盘原来是收起的就保持收起。

5.4 调用 AI 前的检查

适用于：描写助手、改写、扩写、缩写、润色、补细节、描写。按顺序检查，任一步不通过就停止，不自动继续：

  1. 选区超过 2000 字：按钮已禁用（只对选区操作）。
  2. modelServices.getDefault() 为 null → 打开 D03 先连接模型。连接完成回到编辑器后，作者需要再点一次。
  3. prefs.aiNoticeAcknowledged 中没有默认服务的域名 → 打开 D01 AI 数据说明；"知道了，继续"后接着做第 4 步，"取消"则停止。
  4. 没有网络 → 按 G01 离线提示"现在没有网络，AI 暂时用不了。正文的编辑和保存不受影响。"
  5. 立即保存。失败时提示条"正文没有保存成功，暂时不能使用 AI。"
  6. 打开 S08 或 S09。选区快捷操作先展示参考范围与预计消耗，作者确认后才发送（G04）；传入的是点击时的选区（换算为存储偏移）。

5.5 长章节

  1. > 20,000 字（saveBody 返回 'long'）：提示分章，可"知道了"关闭，本次打开期间不再出现。
  2. > 50,000 字（返回 'too_long'）：警告，不可关闭，降到 50,000 字以下后消失。仍然正常保存。
  3. 硬上限 100,000 字：输入或粘贴后 countChars 将超过上限时，这次修改不生效（编辑框回到修改前），提示条见第 3 节。
  4. V1 不提供自动分章。作者自行新建章节，把内容剪切过去。

5.6 进入时的光标

  1. 没有 locate 参数时：光标放在 lastCursor；lastCursor 为 null（从未打开过）时放在正文末尾；超出正文长度时截到末尾。
  2. 进入后自动聚焦正文并弹出键盘，光标所在行滚动到可见区域的上三分之一处。

5.7 "跳到原文"的定位与高亮

参数：locate?: { quote?: string; offset?: number }，至少有一项。来源：S13 传原句和 evidenceOffset；S14a 传本章一侧的原文 quote；S12 出场章节传条目名称作为 quote（无 offset，取第一次出现处）。

  1. 有 quote 且 offset 处正好是 quote（body.slice(offset, offset + quote.length) === quote）→ 命中。
  2. 否则在正文中精确查找 quote 的所有出现位置：有 offset 时取离 offset 最近的一处，没有 offset 时取第一处。
  3. 仍找不到：宽松匹配——两边都去掉空白、半角标点转全角后再找，命中后映射回原正文位置。
  4. 命中：聚焦正文，选中原句（系统选中色，即 brandSelect），滚动到可见区域上三分之一处；选区操作栏随之出现，可直接改写。移动光标或输入后选中自然消失。不另画背景色（TextInput 不支持局部背景色）。
  5. 找不到：有 offset 时光标放在 offset 所在段的段首，提示条"没有找到原句，可能已经改过了。已定位到原来的位置附近。"；没有 offset 时光标按 5.6 恢复，提示条"没有找到原句，可能已经改过或删除了。"
  6. 只有 offset 没有 quote：光标放在 offset（截到正文长度内），不选中。

5.8 保存失败

  1. STORAGE_FULL：弹出对话框"手机存储空间不足，内容没有保存。请清理空间后重试。"（按钮"知道了"，G02 错误码）。编辑框保留内存中的正文，可以继续写；有未保存修改时每 10 秒自动重试，对话框只在第一次失败时出现。重试成功后状态变为"已保存"并提示条"已保存"。
  2. DB_ERROR：按 G01 错误展示弹出对话框（含"复制详情"），不自动重试；作者点"保存失败 · 重试"手动重试。
  3. 保存失败期间，依赖数据库正文的操作（见立即保存）都不执行。
  4. 此时返回：弹出对话框"修改还没有保存"，正文"最近的修改没有存进手机，离开后会丢失。可以先复制全文，清理空间后再粘贴回来。"按钮竖排：复制全文（复制显示文本到剪贴板，提示条"已复制全文"，留在本页）、放弃修改并离开（不保存、不生成快照，直接返回）、留在本页。
  5. 在后台时保存失败：回到前台后显示对话框并继续自动重试。

5.9 离开流程

  1. 通过 React Navigation 的 beforeRemove 拦截返回（含侧滑和 Android 返回键），收起键盘。
  2. 调用 chapters.saveBody(id, body, cursor)（即使正文没变也调用，用于保存光标）。
  3. 保存成功 → 调用 versions.snapshot(id, 'auto')（正文与最近一个快照相同时服务不新建）。快照失败不阻止离开，只记录日志。
  4. 完成后返回来源页面。保存失败 → 5.8 第 4 条。
  5. 打开 S07a、S07c、S08、S09 这类弹层，或进入 S07b 对话框，不算离开，不生成快照。进入 S07d、S12、S14、S14a 等页面时编辑器仍在栈中，只立即保存、不生成快照；从这些页面回来后继续使用原来的撤销栈。

5.10 其他

  1. 冲突提示条：产品设计原文为"点击后选中冲突原文并打开 S14"，本设计按任务说明改为 1 处直达 S14a、多处进 S14 并筛选本章；在 S14a 点"修改正文"回到本页时按 5.7 选中原文。
  2. V1 正文为纯文本，不支持加粗、斜体、标题等格式；粘贴富文本时只保留文字。
  3. 番外和草稿可以使用全部 AI 功能，只是不能定稿、不参与记忆提取。
待确认：进入非空章节时是否自动弹出键盘。本设计为自动聚焦并弹出（保证恢复的光标位置可见、打开即可写）；另一种做法是先以阅读状态打开，点正文再弹出键盘，但 RN 在未聚焦时难以可靠滚动到光标位置。

导出正文（S15b 规则 3）同样在每段前加两个全角空格，与复制出去的效果一致。

6. 边界情况

  • App 被系统杀掉且没有收到后台事件：最多丢失最近 2 秒（连续输入时最多 10 秒）的修改。
  • 拼音输入未上屏时触发自动保存：保存的是编辑框当前内容（iOS 可能含拼音字母），下一次保存会覆盖，不影响结果；撤销合并规则（间隔 < 1 秒）会把组字过程并入一步。
  • 编辑期间后台冲突检测完成并产生本章冲突：提示条出现，不打断输入。
  • 在 S07a"章节信息"中把正文章节改为番外或草稿：定稿本章按钮消失，状态行改为对应徽标。已定稿章节不能直接改类型（G02 会抛出 VALIDATION，由 S06a 显示）。
  • 在 S07a 改字体或字号：立即生效，光标不变。
  • 粘贴超长文本（例如整本小说）：先做 5.5 第 3 条上限检查，再规范化；超过上限时整段粘贴不生效。
  • 全选后选区超过 2000 字：AI 按钮禁用，复制、剪切照常可用。
  • 撤销一步 AI 插入后又重做：正文回到插入后的样子，不再生成新的 before_ai 快照。
  • 定位的原句在正文中出现多次且没有 offset：选中第一处。
  • 读取失败时返回：不调用 saveBody 和快照，避免用空内容覆盖正文。
  • V1 只有单窗口，同一章不会在两处同时编辑。

7. 验收要点

  • 输入后停 2 秒，状态从"保存中…"变为"已保存"；杀掉 App 重进，内容和光标位置都在。
  • 每段段首显示两个全角空格；回车后新段自动缩进；段首按删除键与上一段合并；段首输入的空格被忽略。
  • 数据库中的正文不含段首缩进；复制几段到其他 App，粘贴结果带段首缩进。
  • 字数不计入缩进、空格和换行；选中文字时"已选 N 字"与 countChars 一致。
  • 连续输入一句话撤销一次即可撤回；最多可撤销 100 步；离开再进入后撤销按钮为禁用。
  • 插入 AI 文本后点撤销，正文恢复原样；版本历史中仍有"AI 插入前"版本。
  • 番外、草稿不显示"定稿本章"；已定稿且未修改的正文章节显示禁用的"已定稿"；修改后变为可用的"定稿本章"，状态徽标变为"有修改未定稿"。
  • 选中 2001 字时 AI 按钮禁用并显示原因；选中 2000 字时可用。
  • 未连接模型时点描写助手出现 D03；首次使用某服务域名出现 D01；断网时出现离线提示，正文仍可编辑保存。
  • 本章有 1 处冲突时点提示条进入 S14a；有 3 处时进入 S14 且只显示本章冲突。
  • 从 S13 跳到原文，原句被选中并可见；原句已改动时显示"没有找到原句"提示并定位到附近。
  • 正文超过 2 万字出现分章提示；超过 5 万字出现不可关闭的警告且仍能保存；超过 10 万字的粘贴不生效。
  • 模拟存储已满：出现对话框，内容不丢，10 秒后自动重试；此时返回出现"修改还没有保存"对话框，"复制全文"可用。
  • 修改后返回，版本历史多一个"自动"版本；未修改直接返回不新增版本，章节的更新时间不变。
