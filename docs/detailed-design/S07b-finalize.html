1. 页面功能

  • 本地预览一个永久定稿版本及摘要 → 提取设定变化 → 冲突检查三个任务；列出各任务绑定的服务、模型和请求块，展示整个操作的请求次数、输入估算、输出预留和未知费用。
  • 作者可查看实际发送内容。确认与后台发送使用同一不可变、持久化的 ContextPlan；正文、设定、服务绑定或策略变化必须重新预览。
  • 定稿本地事务不依赖网络。缺服务或范围过大时仍可保存定稿，但 AI 作业保持暂停；接入新服务不会追溯绑定或自动重发旧任务。

2. 元素与操作

#元素显示与操作
1标题首次“定稿「第 N 章 {标题}」？”；modified 为“重新定稿…”，标题超过 12 字截断。
2说明与预算说明永久版本、摘要、设定建议与冲突检查；正式设定由作者确认。逐项展示路由服务/模型/请求块；整个操作 N 次计划请求、最多 N+2 次 POST、预计输入与总输出预留，可靠价格缺失则明确“费用未知”。
3整理范围和暂停提示使用 FinalizationPreview.incremental、reason、eligible。无有效服务绑定为 no_service，单段过长或必要上下文无法容纳为 budget；超过 6 个未缓存块时显示首批范围和整作业消耗，允许仅保存定稿或显式授权首批最多 6 块，后续在 S05b 单独授权；说明定稿仍保存在本机，AI 暂停。当前不在本框按系统网络状态或默认服务 Key 预判；绑定服务 Key 与 D01 在 claim / S05b 检查。
4取消 / 查看发送内容取消关闭确认且不创建永久正文版本或任务；本地预览载荷可按 LRU 清理。“查看发送内容”展示每个请求块捕获的服务、模型与序列化请求，返回后继续使用原预览。
5定稿本章 / 重新定稿调用 chapters.finalize(chapterId,{plan,authorizeFirstBatch})；长作业显示“仅保存定稿”和“保存并执行第 1–6 块”，分别传 false / true；提交中禁止重复点击和关闭。成功更新章节状态及任务；同一 planId 重复确认幂等，不创建第二批请求。失败反馈后重新预览确认，不能悄悄改用新服务。

时机调用与规则
打开前S07 立即 chapters.saveBody，失败则不打开确认。
打开确认features/finalizationPlans.previewFinalization(chapterId) 在本地构建并持久化原 ContextPlan。按 utility / review 显式绑定解析服务，无绑定才取当时默认；不存在的绑定不改用其他服务。
作者确认chapters.finalize(chapterId,{plan}) 在一个事务校验原预览、正文、完整输入指纹、策略、服务 revision 和服务绑定；保存/绑定 finalize 版本，更新 finalizedVersionId，使旧任务/旧 token 失效，复用完全匹配的已完成任务或入队新任务、块及共享父预算。事务提交后 emit。
前台执行features/finalizationRunner 按已确认块执行，每块校验后 checkpoint，整项完成才经 jobs.commit 在同一事务复核版本/依赖/token 并写摘要或待审核提案/冲突。

5. 业务规则

情况提取范围
首次定稿 / 缺少可信覆盖基线全章按完整段落分块。上一版提取未完成，或仍有旧 pending 提案时，不能假设已覆盖，保守全量。
重新定稿且有可信基线只对新增/改动段落附邻段提取。纯删除仍分析存续边界并提出旧证据退休审核；纯重排保守全量。摘要和冲突检查覆盖完整定稿，不以摘要代替提取证据。
  1. 只有有正文的 main 章节可以定稿；番外与草稿不启用该操作。
  2. 离线或服务缺失不阻止本地定稿。no_service 作业后来接入服务仍需重新预览确认；缺 Key 或未确认 D01 在执行前暂停，由 S05b 作者处理。无网络时不承诺自动识别 offline；请求网络错误/超时/流中断保守暂停 interrupted，联网不自动重放。
  3. 整个作业最多 N+2 次 POST，每块最多 3 次；有限重试、参数降级共用预算。手动继续沿用已用次数、输出预留和原期限，不清零。中断请求可能已计费，必须作者再次确认。
  4. 成功提示显示已定稿并排队，计划不可执行时显示 AI 整理已暂停。当前提示条 4 秒；任务详情由 S05b 查看，不承诺尚未实现的自动完成提示或提示条跳转。
  5. 重新定稿取消未完成旧任务，完整依赖相同的已完成结果才复用。旧提案与冲突保留来源，已失效者只读；来源正文、档案或服务变动后的迟到结果不得写回。
  6. 正文与定稿版本不同即 modified；作者仍可编辑，AI 不直接改变正文或正式档案。提案由 S13 审核，冲突由 S14 处理。

6. 边界情况

  • 确认期间正文/档案/顺序/服务或绑定变化：原预览失效，重新预览确认；回前台不重建后直接发送。
  • 重复点击或事务后确认重入：同 planId 返回已创建任务，不重复生成父作业或请求。
  • 长章节不静默截取正文。按完整段落分块；超过 6 个未缓存请求块时保留整章计划，先展示范围和整作业消耗，由作者明确授权首批最多 6 块，或仅保存定稿。后续在 S05b 逐批确认，全部批次共享原 N+2、输出预算和期限，不自动续批。单段过长或必要上下文容不下才暂停 budget，要求拆章重新预览。
  • 退到后台或崩溃后有当前块尝试记录：暂停 interrupted，已验证块不重发，未知费用不记零。无当前块尝试记录、已获批次授权且完整依赖有效时才可恢复 queued，未授权块继续暂停 batch。
  • 定稿后删除章节或撤销定稿：取消未完成任务、撤销执行 token，旧结果不能提交；永久定稿快照仍按版本/回收站规则保留。

7. 验收要点

  • 确认前可看实际请求、所有路由、整作业预算和未知费用；预览与发送保持同一不可变计划。
  • 本地定稿在缺服务、离线时可成功；新增服务/网络恢复不直接重发旧任务，失效绑定必须重新确认。
  • 首次或无覆盖基线全量；有效基线才增量，删除/重排不漏检，长章不静默截断。
  • 重复确认幂等，重新定稿取消旧活动任务；迟到结果、过期提案与冲突不能覆盖正式内容。
  • 取消确认后不创建正文版本或任务。当前离线测试不能替代真实双端强杀、后台和模型效果验收。
