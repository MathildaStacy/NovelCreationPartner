1. 页面功能

  • 编辑 ModelService 的 name 和 options 中可由作者修改的字段：maxOutputTokens、effort、authHeader、store、contextBudget（G02 第 2 节）。
  • 只读显示 options.caps（App 在调用中自动探测的能力），并允许清除重新探测。
  • 按协议只显示适用的字段。
  • 所有改动只写入 S02 的草稿，随 S02 的"保存"一起入库；本区域没有单独的保存按钮。

4. 数据与本地服务

本区域不直接调用本地服务，读写的都是 S02 的草稿：

draft.name                         // 名称，'' 表示保存时生成自动名称
draft.options.maxOutputTokens      // number | null，null = 按任务默认（G03 第 6 节）
draft.options.effort               // 'default' | 'low' | 'medium' | 'high'
draft.options.authHeader           // 'x-api-key' | 'bearer'，仅 Anthropic 生效
draft.options.store                // boolean，仅 OpenAI 生效，默认 false
draft.options.contextBudget        // number，默认 24000
draft.options.caps                 // 只读显示，可整体清空为 {}

进入编辑模式时由 S02 的 modelServices.get(serviceId) 填入；新建时取第 5 节规则 1 的默认值。保存走 modelServices.save(draft, key)，见 S02 第 5 节。

各字段在请求中的用法：

字段OpenAI ResponsesAnthropic Messages
maxOutputTokensmax_output_tokens；null 时用任务默认值max_tokens；null 时用任务默认值
effortreasoning.effort；'default' 时用任务默认值output_config.effort；同左
authHeader不适用，固定 Authorization: Bearerx-api-key 或 Authorization: Bearer
store请求体 store不适用
contextBudget本地上下文组装的输入上限（G03 5.1），不作为请求参数发送

来源：G03 2.2。连接测试固定用最大输出 64、最低推理强度，不受本区域的最大输出和推理强度影响（G03 6.1）。

5. 业务规则

  1. 默认值：名称空、maxOutputTokens = null、effort = 'default'、authHeader = 'x-api-key'、store = false、contextBudget = 24000、caps = {}。
  2. 最大输出：空 → null。否则必须是 1–128000 的整数（全角数字转半角，去掉千分位逗号），不合法时"请填写 1 到 128000 之间的整数，或留空"。1–3999 时允许保存，但下方琥珀色提示"低于 4000 时，描写、讨论和整理结果容易被截断。"超过所选模型的实际上限时，App 不在本地拦截，由服务返回 AI_BAD_REQUEST，S02c 中给出提示。
  3. 输入预算：必须是 8000–100000 的数，失焦时四舍五入到最接近的 1000；空或不合法时"请填写 8000 到 100000 之间的数"。
  4. 哪些改动影响测试结果：只有鉴权头属于连接字段（与协议、Base URL、Key、模型一样会清空测试结果、中止测试）。名称、最大输出、推理强度、服务端保存、输入预算的改动不清空测试结果，也不清空 caps（S02 规则 11）。
  5. 改动判断：本区域所有字段（含"清除能力记录"）都计入 S02 的改动判断，有改动时返回会弹 D04（S02 规则 8）。
  6. 不提供的设置（V1 刻意不做，避免作者调出不能用的组合）：
    • 温度、top_p："创意度"滑杆不提供。当前 Claude 模型只接受 temperature = 1，GPT-6 系列开启推理时不允许设置；App 从不发送这两个参数（G03 2.2）。
    • 超时：固定为首字节 60 秒、流中断 90 秒、连接测试 20 秒（G03 第 3 节），不可调。
    • 流式开关：总是请求流式；服务不支持时自动按非流式处理并记入 caps.streaming（G03 第 3 节"非流式兜底"）。
    • 结构化输出强制开关：由 App 自动探测和降级（G03 4.2），作者只能用"清除能力记录"让它重新探测。
    • 自定义请求头：只能切换 Anthropic 鉴权头；anthropic-version 固定为 2023-06-01。

6. 边界情况

  • 从备份恢复的服务：options 随备份恢复（G02 5.13），本区域按恢复后的值显示。
  • 在 OpenAI 下把"不在服务端保存"关掉后切到 Anthropic 再保存：store = true 原样保存但不生效；切回 OpenAI 时开关显示为关。
  • 粘贴 "16,000" 到最大输出：按 16000 处理。粘贴 "16k"：报格式错误。
  • 点"清除能力记录"后没保存就返回：弹 D04；放弃后原能力记录不变。
  • 修改了推理强度为"高"，但服务探测为不支持：保存后请求中不发送该字段，界面在第 4 项说明里告知，不报错。
  • 收起折叠区时某字段有错误：折叠行副标题改为红字"有 1 项需要修改"。

7. 验收要点

  • Anthropic 协议显示"鉴权头"不显示"不在服务端保存"；OpenAI 相反；来回切换后两者的值都保留。
  • 名称留空保存，服务名为"Anthropic"（官方地址）或主机名；填写与其他服务相同的名称时报"已有同名的模型服务「…」"并展开本区域。
  • 最大输出填 0、128001、"abc" 均报错；填 2000 可保存并显示截断提示；留空保存后为 null。
  • 输入预算填 25400 失焦后变为 25000；填 5000 报错。
  • OpenAI 服务"不在服务端保存"默认开，抓包可见请求体 store: false；关掉后为 store: true。
  • 改鉴权头会清空测试结果；改推理强度、最大输出不会。
  • 结构化输出被探测为不支持后，本区域显示"不支持"；点"清除能力记录"并保存后显示"未探测"，下一次结构化任务重新尝试原生参数。
  • 本区域没有温度、超时、流式、自定义请求头的设置项。
