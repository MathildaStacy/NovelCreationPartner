1. 页面功能

  • 列出本作品由章节定稿和作者确认的重新冲突检查产生的持久任务。全局前台串行执行；页面沿服务返回的创建顺序以 FlatList 显示，保留暂停、失败、完成和取消记录。
  • 每项显示绑定章节、状态、执行次数、已验证块数及整作业请求/输出预算。用量未知不记为零，不把部分块完成称为完整整理。
  • 暂停和失败由作者按原因处理；连接服务、回到前台或联网均不会把暂停任务自动排队。正式设定和正文仍由作者确认后改变。

2. 元素与操作

#元素显示与操作
1批量重试当前不提供“全部重试”，避免跳过每项的中断计费确认。分组和批量操作仍为未完成的界面项。
2暂停原因在各任务行显示原因，第 5 节列出处理方式；当前没有自动恢复横幅。Key 与 D01 均针对任务绑定服务。
3–4任务行与状态任务名、章节、状态、执行次数、请求块进度；有 operationId 时显示整个作业的计划请求数、已尝试/最大次数、输出已预留或使用/总上限，以及未知用量次数。任务 attempts 是成功领取的执行次数，物理 POST 另见父账本。
5取消任务未 done/cancelled 显示。取消摘要先确认“取消后续任务？”，确认后逐项取消同 operationId 未完成任务，已完成结果保留；其他任务仅取消本项。写入 cancelled 并撤销 token，runner 收到事件中止，迟到结果拒绝写回。
6继续 / 确认后重试paused / failed 中可恢复项显示“继续”；interrupted 显示“确认后重试”，明确提示上次可能已计费，再调用 jobs.resume(id,{confirmInterrupted:true})。no_service / legacy_input / stale / budget 仅提供“前往章节重新定稿”。batch 显示“预览并授权下一批”，列出连续最多 6 个原请求块的实际服务/内容、本批消耗、父作业剩余次数和原期限；返回或取消不授权，确认使用同一预览，不自动续批。没有 jobs.retry 或清零尝试次数的操作。
7查看详情存在 Job.error 时可打开 D05，保留统一安全详情与复制规则。
8完成结果done 的提取任务可进入 S13，检测任务进入 S14；摘要保存在章节上。当前沿列表显示，不承诺“最近 20 条”的独立分组。

3. 页面状态

状态表现
加载 / 加载失败复用本地加载状态；失败显示“任务没有加载出来。”及重试。
空“还没有后台任务”，说明定稿后摘要、设定提取与冲突检测会出现在这里。
暂停 / 失败保留任务、错误、已验证进度和父预算，各项操作按第 5 节处理。
操作失败通过 G01 错误反馈。输入或服务失效时拒绝恢复并要求重新定稿；预算不足不扩大额度；取消中断确认则保持原暂停状态。

4. 数据与本地服务

时机调用与规则
进入及刷新jobs.list(workId)、chapters.list(workId)、aiUsage.forRequest(operationId)；订阅同作品 jobs.changed / chapters.changed 与 usage.changed。
作者继续读取绑定的 modelServices.get(serviceId)；缺 Key 导航到该服务的编辑页。未确认绑定域名时先 D01，同意后保存确认并调用 jobs.resume。服务配置修改导致 revision 变化时旧任务失效，不能换用当前默认绕过。
取消jobs.cancel(id)，摘要按已确认的同作业未完成项逐项调用。done 不回退为 cancelled。
配置服务、返回前台执行器只检查 queued；不自动恢复 no_service / no_key / interrupted。连接新服务后，未绑定旧任务须重新预览并确认定稿。

5. 状态与恢复规则

状态原因与操作
queued等待全局执行器及同作业前序任务；前序提取已取消时允许继续检测。不能从 attempts 推断“还可自动重试几次”。
running执行绑定的不可变请求块；每块校验后保存 checkpoint，整项完成才提交派生结果。
paused · no_service“未绑定模型服务，请重新确认定稿”；新服务不会补写旧任务绑定，前往章节重新预览。
paused · no_key“绑定服务缺少 API Key”；继续会打开该服务填写 Key。保存引起服务 revision 变化时须重新定稿，不自动恢复旧计划。
paused · notice“需要确认数据说明”；作者点继续并同意绑定域名的 D01 后才请求恢复。
paused · interrupted“请求中断，可能已计费，等待你确认”；确认后沿用父预算、子请求已用次数和原期限，不保证还有可用额度。
paused · legacy_input / stale / budget分别表示旧任务无绑定输入、定稿/依赖/服务变化、整个作业达到预算或预览范围过大；前往章节重新预览定稿，budget 需缩小范围/拆章，不扩大旧作业预算。
paused · batch等待作者授权下一批。仅同作业首个未完成任务显示批次入口；jobs.previewNextBatch 在本地预览原请求，jobs.authorizeBatch 原子核验后持久授权。未授权块不发送，不将部分完成称为整项完成；已用预算和原期限不变。
paused · offline保留的兼容状态，当前可显示“等待网络”并由作者继续；执行器不订阅联网状态，不承诺自动设置或恢复该状态。
failed显示 Job.error。作者可继续、查看详情或取消；执行中取消/网络/超时/流中断保守进入 interrupted，预算与失效另进入对应暂停原因。
done / cancelled保留完成结果或取消记录，不通过 resume 重新排队。
  1. 每块最多 3 次物理尝试；所有块、有限退避重试和参数降级共享整作业 N+2 次 POST 与输出预留。自动重试只针对没有输出且可重试的限流/服务错误；网络失败或已产生输出不自动重发。
  2. 手动恢复不清零 attempts、物理次数、输出预留或原期限。领取前条件不满足不增加 attempts；领取后因中断暂停保留执行计数。
  3. 退到后台中止当前请求，runner 保守暂停 interrupted；依赖已失效则 stale。回到前台只唤醒 queued，不直接重发中断请求。
  4. 启动先恢复账本，再检查 running 的当前首个未完成块。该块有尝试记录即暂停 interrupted；只有无当前块尝试记录、当前块已获授权且绑定、输入、依赖仍有效才回 queued；未授权块保持 batch。已验证块可复用检查点；所有块已完成时可继续本地提交。
  5. 取消不可撤销；重新定稿需新预览和作者确认。旧提案、旧冲突保留来源，失效后只读，不能作为当前正式设定直接采纳。

6. 边界情况

  • 点取消时任务恰好 done：保留 done，刷新列表，不能把完成结果回退为取消。
  • 绑定服务在排队时删除：claim 暂停 no_service；启动恢复检测到旧服务依赖无效可暂停 stale。不会换到其他默认服务。
  • 切换默认服务或可选任务绑定：已发布作业继续使用已确认快照；尚未确认的预览必须重新核对绑定。
  • 断网请求无法确认终态：保守暂停 interrupted，可能已计费；联网不触发自动重放。
  • 在 D01 不同意或中断重试提示中取消：保持暂停与原账本不变。
  • 作业超过 6 个未缓存请求块：确认前展示整作业消耗，逐批最多授权 6 块，后续批次保持 batch 暂停。单段或必要上下文过大则暂停 budget 并要求拆章；批次确认不能绕过硬上限、服务/依赖校验或原期限。

7. 验收要点

  • 已确认且依赖有效的作业串行执行，显示块进度和整作业预算；完整缓存可以复用，不要求重复发送三个任务。
  • 未绑定模型时定稿本地成功；后来新增服务不会自动发送旧任务，须重新预览确认。
  • 网络中断、切后台和强杀恢复有当前块尝试记录时，暂停等待作者确认，不自动重放；确认后已用预算保持。
  • 服务删除/修订或输入失效后不换默认服务、不写旧结果，要求重新定稿。
  • 取消摘要明确确认后取消同作业未完成项，已完成结果保留；提取/检测完成入口打开对应审核列表。
  • 离线 SQLite/合成协议/UI fixture 仅验证状态和边界；真实后台、强杀、设备生命周期与模型质量仍需实测。
