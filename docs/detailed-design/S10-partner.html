1. 页面功能

  • 按对话组织讨论：显示当前对话的全部消息，可新建对话、进入对话列表切换。
  • 顶部上下文条显示本对话的参考范围和实际带入的设定数量，可进入 S10a 参考范围调整。
  • 发送消息并流式显示 AI 回复；生成中可以停止；出错时在消息内说明原因并可重试。
  • AI 回复除普通文本外，还有三块结构化内容：已明确、还需要你决定（问题可点，引用到输入框）、可选方向（提议卡）。
  • 对每个方向：采纳为设定（经 S10c 预览后写入档案，状态为已确认）、暂存（直接写入档案，状态为提议）、改一改（带回输入框）、撤销。
  • 快捷提示：换一批、对比方案（进入 S10d）、预设提示语。
  • 长按消息打开 S10e 消息操作（复制、重新生成、查看模型与用量）。
  • S04 的“和 AI 一起想”创建作品后预填问题草稿，由作者显式预览并发送。
  • 切换底部标签不打断生成；离开作品时停止生成并保存已生成的部分。

4. 数据与本地服务

进入页面

  • 调用 conversations.list(workId)。当前对话按以下顺序确定：路由参数中的 conversationId → 本次打开作品期间上次查看的对话（内存中记录）→ 列表第一条（最近有消息的）→ 没有对话时为空的新对话。
  • 调用 conversations.messages(conversationId)，渲染全部消息（列表虚拟化）。
  • 确定参考范围：对话已保存的范围；新对话用 prefs.get('partnerScope') 生成默认范围（规则见 S10a 规则）。再调用 ai.previewContext 得到上下文条的数字。
  • 路由参数带 seed（来自 S04"开始构思"）时，把灵感预填到输入框，见下方"预填灵感"。
需要新增：ai.previewContext(workId, scope, conversationId?) → { items: { kind: 'work'|'history'|'chapter'|'summary'|'entry', entryId?, label, state?, tokens, included }[], totalTokens, budget, truncated } —— 按 G03 上下文组装的同一套逻辑在本地计算将带入的内容和估算 token，不调用模型。S10 上下文条和 S10a 共用。

订阅事件

  • messages.changed（当前对话）：重新读取消息。生成中服务层每 100 ms 至多发出一次，界面只更新最后一条消息，滚动位置按规则 8 处理。
  • conversations.changed：刷新标题和参考范围；当前对话被删除时切换到列表第一条，没有则显示空状态。
  • entries.changed：重新计算上下文条；方向卡的状态以消息中记录的选项状态为准，不因档案变化自动改变。
  • chapters.changed：参考范围为"仅某章相关"时重新计算上下文条（章节可能被删除或改名）。

调用 AI 前的检查

本页所有会调用模型的操作（发送、快捷提示、换一批、重试、重新生成、暂存、采纳为设定、对比方案）在调用前按顺序检查，任何一步不通过就停在原处，不创建消息、不改变卡片状态，输入框内容保留：

  1. 网络：没有网络时按 G01 离线提示。
  2. 模型服务：modelServices.getDefault() 为 null 时打开 D03 先连接模型。连接完成回到本页后不自动继续，你再点一次即可。
  3. AI 数据说明：默认服务的域名不在 prefs.aiNoticeAcknowledged 中时打开 D01 AI 数据说明；点"知道了，继续"后自动继续原操作，点"取消"则停止。

S10c、S10d、S10e 中的 AI 操作也使用这一检查。

发送流程

  1. 校验输入（规则 4），做上面的检查。
  2. 当前是空的新对话时，先 conversations.create(workId, { seed: text })（标题取前 16 字），再用当前范围 conversations.setScope。
  3. conversations.send(conversationId, text, { scope, mode })，得到 { userMessage, assistantMessageId }；清空输入框，滚动到底部。服务层随后调用 ai.ideate，经 conversations.appendAssistant 流式写入，完成时写入 structured、usage、status。
  4. 每条 AI 消息记录发送时的默认模型服务（serviceId、model），之后更换默认服务不影响已有消息。
需要修改：conversations.send(id, text, { scope, mode }) —— 增加 mode: 'chat' | 'more_options'（默认 chat），透传给 ai.ideate；scope 改为对象 PartnerScope = { kind: 'confirmed'|'chapter', chapterId: ID|null, includeProposed: boolean }。另需说明：conversations.create 的 seed 只用于生成标题，不写入消息，第一条消息统一由 send 写入，避免重复。
需要新增：conversations.setScope(id, scope: PartnerScope) —— 保存对话的参考范围；Conversation 增加 scope 字段（表 conversations 增加 scope TEXT，JSON）。发出 conversations.changed。
需要新增：conversations.stop(messageId) —— 中止该消息正在进行的生成（服务层持有其 AbortController），把已生成文字以 status = stopped 保存。生成由服务层持有而不是页面持有，这样切换标签不会中断。

预填灵感（从 S04 进入）

  1. S04 在点"开始构思"时已完成 D03、D01 检查并创建作品，然后以参数 { seed: premise } 进入本页。
  2. 本页把灵感填入输入框，不自动发送（G04 发送前预览、D03 第 3 节不自动续发，2026-10-19 作者确认）；作者点发送后按"发送流程"预览、创建对话并发送。离线时按 G01 离线提示。

切换标签与离开作品

  • 切换底部标签：本页保持挂载，滚动位置、输入框内容、展开状态都保留；生成继续进行，回来时直接看到最新进度。
  • 切换对话（经 S10b）：正在生成的回复继续在原对话中生成；每个对话的输入框草稿在内存中分别保留，直到 App 退出。
  • 离开作品（返回书架，见 G01 导航）：作品容器卸载前，对该作品所有生成中的消息调用 conversations.stop，已生成部分以已停止保存。
  • App 进入后台：不主动停止。系统中断连接时按网络中断处理（消息变为出错，可重试）。
  • App 被结束：下次启动时，遗留的 streaming 消息改为 stopped。
需要新增：G02 第 10 节启动流程增加一步 —— 把 messages.status = 'streaming' 的记录改为 stopped。

5. 业务规则

  1. 当前对话：见第 4 节"进入页面"。对话列表按最后消息时间倒序（conversations.list）。
  2. 新对话延迟创建：点"新对话"只切换到空界面，发送第一条消息时才调用 conversations.create，避免产生空对话。空的新对话不出现在 S10b 中。
  3. 上下文条文案（数字来自 ai.previewContext，只统计预算内实际带入的条目）：
    • 相关已确认设定："参考 N 条已确认设定"。N 含已确认、正文已建立、有冲突的条目。
    • 仅某章相关：正文章节"参考第 12 章与 N 条相关设定"；番外或草稿"参考番外「灯塔守夜人」与 N 条相关设定"。
    • 带入了提议状态的条目且 M ≥ 1 时，末尾加" · M 条提议"。
    • 有内容因超出预算没有带入时，末尾加"（部分超出预算）"。
    • N = 0 且没有提议：全部范围显示"还没有已确认的设定，只参考作品信息和对话"；章节范围显示"参考第 12 章，没有相关设定"。
  4. 输入长度：去掉首尾空白后 1–2000 字（按字符计，换行计 1，emoji 计 1）。达到 1800 字时在输入框右下角显示"1856/2000"；超过 2000 时计数变为错误色，发送禁用，不自动截断。
  5. 引用问题：插入文本为"关于「{问题}」："。输入框为空时直接填入；不为空时另起一行追加。可以连续引用多个问题，一次回答。
  6. 改一改：插入文本为"基于方向「{标题}」：{一句话概括}走向：{走向}"，后接换行，光标停在末尾等你写修改意见。输入框为空时直接填入；不为空时另起一行追加。追加后超过 2000 字时只追加前缀和概括。
  7. 时间分隔：对话第一条消息前，以及相邻两条消息间隔 ≥ 10 分钟时，显示居中的时间（G01 时间格式）。
  8. 自动滚动：发送后滚动到底部。生成中，你停留在距底部 80 px 以内时跟随新内容滚动；向上滚动后停止跟随，出现"↓ 回到最新"。
  9. 同时生成：整个 App 同一时间只允许一条 AI 伙伴回复在生成。其他对话的发送按钮禁用并说明原因。
  10. 结构化部分只在消息状态为完成且 structured 非空时显示。问题最多 3 个，方向 2–3 个（产品设计 7.3）；超出时只显示前 3 个。三块中某块为空时整块不显示。
  11. 空状态示例问题（固定）："帮我梳理一下目前的主线""主角的动机还缺什么""下一章可以发生什么转折"。
  12. 选项状态：open → adopted（经 S10c）、open → stashed（暂存）、adopted / stashed → open（撤销）。stashed 不能直接变为 adopted：如需正式采纳，在 S12 中逐个采纳提议字段，或先撤销暂存再采纳。dismissed 状态 V1 界面不使用。
  13. 换一批：发送固定文本"换一批方向"，以 more_options 模式生成；新方向不得与本对话已出现的方向重复（由 G03 提示词保证）。
  14. 写入来源：暂存和采纳写入档案时，来源均为 { kind: 'partner', ref: '{messageId}#{选项序号}' }，档案中显示为"来自 AI 伙伴"。

6. 边界情况

  • 暂存或采纳的条目之后在档案中被删除或修改：点"撤销"时返回 CONFLICT_STATE，提示"这些设定之后改过，请到档案里手动调整"，卡片保持原状态。
  • 同一张卡正在暂存时：本卡三个按钮禁用；其他卡仍可操作，可以同时进行。
  • 暂存进行中切换标签：拆解和写入继续完成，回来后卡片已是新状态。离开作品时拆解请求被中止，卡片保持 open，不写入任何内容。
  • 重新生成一条已有采纳或暂存的回复：先在 S10e 确认；已写入档案的设定保留，但新回复中不再有对应的"撤销"。
  • 生成中途默认模型服务被删除或修改：当前请求不受影响，继续使用已读取的配置。
  • 参考范围选择的章节被删除：上下文条自动改为"相关已确认设定"，并提示条"参考的章节已删除，已改为相关已确认设定"。
  • 当前对话在 S10b 被删除：回到本页时显示列表中的下一个对话；如果被删除的对话正在生成，先停止再删除。
  • 连续快速点击"发送"：第一次点击后立即禁用按钮，直到消息写入完成，不会重复发送。
  • 对话很长（≥ 500 条消息）：消息列表使用 FlatList 虚拟化，所有消息仍可滚动查阅，初始 / 每批 8 条，窗口 7 屏；发给模型的历史按 G03 预算截取最近的部分，界面数据不裁掉旧消息。流更新不强制滚动，完成后沿用滚到底部；距底 80 px 跟随与“回到最新”仍待设备交互完善。
  • AI 回复里只有结构化内容、没有普通文本：直接从"已明确"开始显示。

7. 验收要点

  • 从 S04 点"开始构思"进入后，灵感已预填在输入框；预览并发送后 AI 回复包含已明确、最多 3 个问题、2–3 个方向卡；返回再进入不会重复发送。
  • 点问题，输入框出现"关于「…」："；点"改一改"，输入框出现"基于方向「标题」："开头的内容，都不自动发送。
  • "暂存"后档案中出现状态为提议的条目，卡片显示"已暂存为提议"；点"撤销"后档案中这些提议消失。
  • "采纳为设定"写入后卡片收起为一行，档案中条目为已确认；撤销后恢复为提议卡，档案恢复原状。
  • 采纳后在档案中修改了该条目，再点"撤销"，提示"这些设定之后改过，请到档案里手动调整"，档案不变。
  • 最后一条回复只有 1 个未处理方向时，"对比方案"置灰；有 2 个及以上时可进入 S10d。
  • 生成中发送按钮变为"停止"；停止后保留已生成文字并显示"已停止生成"。
  • 断网发送：不产生新消息，输入内容保留，显示离线提示。生成中断网：消息显示错误原因和"重试"，重试成功后原位置替换。
  • 没有模型服务时点"发送"出现 D03；首次使用某服务域名时出现 D01，点"知道了，继续"后消息发出。
  • 生成中切换到"章节"标签再回来，生成没有中断，滚动位置不变；返回书架后再进入，该消息显示"已停止生成"且保留已生成部分。
  • 输入 2001 字时发送按钮禁用，计数为错误色。
  • 点"新对话"后不发送任何消息再进入 S10b，列表中没有空对话。
