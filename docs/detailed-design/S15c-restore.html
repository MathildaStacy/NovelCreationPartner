1. 页面功能

  • 用系统文件选择器选一个 .ncpbak 文件，backup.inspect 校验格式版本与完整性并返回摘要。
  • 预览备份中的作品（书名、章节数、字数）和模型服务数，作者勾选作品、决定是否恢复模型服务配置。
  • backup.restore 一个事务导入；成功后提示结果并引导补填 Key。
  • 只有"合并导入"一种方式：G02 的恢复以新 ID 导入、不覆盖现有作品，MVP 不提供"覆盖 / 清空后恢复"。想替换时，作者先删除旧作品再恢复。

5. 业务规则

  1. 不覆盖、可重复：同一个备份恢复两次会得到两份作品（第二次也加"（恢复）"；已有"X（恢复）"时再次同名加"（恢复 2）"，依次递增）。现有作品、章节、档案、模型服务都不被修改。
  2. 恢复的内容：备份里所选作品的全部数据（含草稿、番外、历史版本、档案、对话、提案、冲突、封面）。后台任务不恢复；恢复的作品不会自动排 AI 任务。偏好不在备份中，保持本机设置。
  3. 确认对话框：标题"恢复 N 部作品？"；正文"将作为新作品加入书架，不会覆盖现有作品。"勾选模型服务时追加"模型服务配置不含 API Key，恢复后需要重新填写。"；按钮"取消 / 恢复"。
  4. 成功后：
    • from:'welcome'：写 onboardingDone，导航栈重置为 S03 书架。
    • from:'shelf' / 'settings'：返回来源页（书架随 work.created 刷新）。
    • 提示条"已恢复 N 部作品"；恢复了模型服务时改为对话框"作品已恢复。备份不含 API Key，请为恢复的模型服务重新填写 Key。"按钮"稍后 / 去填写"，"去填写"进入 S15（服务行显示"需要填写 Key"，点击后经 S15a"填写 Key"进 S02）。
  5. 模型服务的合并：恢复的服务若与现有服务同名，服务层按 S02 名称唯一规则在名称后加"（恢复）"。手机上已有默认服务时默认不变；原本没有任何服务时，恢复的第一个服务成为默认（缺 Key，AI 操作时 D03 显示"填写 Key"）。
  6. Key 不跨设备：Key 存于 iOS Keychain（THIS_DEVICE_ONLY）/ Android Keystore，备份从不包含，恢复后必须由作者重新填写。
  7. 完全离线：校验和恢复都在本机完成，不联网。

6. 边界情况

  • 选了 TXT / Markdown 或其他 zip：BACKUP_INVALID。Android 文件选择器无法按扩展名过滤时同样由校验兜底。
  • 备份中 0 部作品、0 个服务：预览显示"这个备份里没有作品"，主按钮置灰。
  • 恢复中 App 被杀或切后台被回收：事务未提交，数据不变；来自 S01 时 onboardingDone 仍为 false，下次启动仍是欢迎页。
  • 文件来自云盘尚未下载完：系统选择器负责下载；读取失败按 BACKUP_INVALID。
  • 备份很大（数百 MB 封面）：存储不足时 STORAGE_FULL，整体回滚。

7. 验收要点

  • S01、空书架、S15 三处入口都能进入；从 S01 取消返回欢迎页，成功后进入书架且重启不再显示欢迎页。
  • 损坏文件、TXT 文件、较新格式版本文件分别显示对应文案，且数据库无变化。
  • 在同一台手机恢复刚导出的备份：现有作品不变，新作品带"（恢复）"，章节、版本、档案、关系、封面完整。
  • 取消勾选的作品不被导入；不勾选模型服务时服务列表不变。
  • 恢复的模型服务在 S15 显示"需要填写 Key"；未填写前使用 AI 弹 D03。
  • 人为让导入中途失败（测试桩），数据库与恢复前完全一致。
