1. 页面功能

  • 一页完成一个模型服务的全部配置：协议、Base URL（实时显示实际请求地址）、API Key、模型。名称、鉴权头、最大输出、推理强度等放在折叠的 S02b 高级设置。
  • "从列表选择"向服务请求模型列表，在 S02a 中搜索并选择；列表拿不到时仍可手填模型名。
  • "测试连接"用当前填写的内容（不必先保存）发一次最小请求，结果原地显示（S02c）。
  • 保存不强制要求测试成功，但没测试或测试失败时会先提醒一次。
  • 编辑已有服务时，Key 输入框留空表示保留原来的 Key。

5. 数据与本地服务

进入页面

  • edit 模式：modelServices.get(serviceId) → ModelService & { keyMask }。其他模式不读数据。

订阅事件

  • 无。本页编辑的是草稿，保存前不受外部变化影响。

草稿结构

draft = { id?: ID, revision?: number, name: string, protocol, baseUrl, model,
          options: { maxOutputTokens, effort, authHeader, store, contextBudget, caps } }
keyInput: string      // Key 输入框内容；edit 模式为空表示不修改

caps 由本页维护：协议、Base URL、模型任一改动时清空为 {}（G03 4.2）；测试中探测到的能力（如 caps.streaming、caps.effort）写回草稿，随保存一起入库。

测试连接、获取列表

  • modelServices.test(draft, key, {signal})、modelServices.fetchModels(draft, key, {signal})。key 取 Key 输入框内容；edit 模式且输入框为空时传 undefined，由服务层读取 draft.id 已保存的 Key。
  • 这两个调用不经过 D03 / D01（G03 第 1 节、D01）：只发送"ping"，不含作品内容。

保存

  1. 校验全部字段（规则 3–6，以及 S02b 的字段）。失败则停在本页显示字段错误。
  2. 判断测试情况：本页打开后没有测试过，或最后一次测试之后连接字段有改动 → 弹出对话框"还没有测试连接"，正文"不测试也可以保存。地址、Key 或模型有误时，要到第一次使用 AI 时才会发现。"，按钮"先测试" / "直接保存"。最后一次测试失败且之后没有改动 → 对话框"连接测试没有通过"，正文为失败原因一句话，按钮"继续修改" / "仍然保存"。edit 模式下连接字段和 Key 都没改动时不弹这两个对话框。
  3. 调用 modelServices.save(draft, key, testResult?)：key 为 Key 输入框内容（已按规则 5 清理），edit 模式输入框为空或仅显隐读出但未经编辑时传 undefined。仅把仍匹配当前连接字段的 TestResult 原对象传入；服务层按 G02 5.11.3 验证并生成 lastTest/caps，不在草稿中拼装 lastTest。
  4. 成功返回 {service, keyCleanupPending}，services.changed 由服务层发出；按规则 9 离开本页。keyCleanupPending 时提示「已保存，旧 Key 待设备解锁后清理」，S15 保留待清理状态。
  5. 失败：DUPLICATE（名称重名）→ 展开高级设置，名称框下显示错误；KEY_UNAVAILABLE → 对话框"无法保存 API Key，请解锁手机后重试。"；STORAGE_FULL / DB_ERROR 按 G02 错误码。业务提交前失败保留旧配置和旧 Key，新槽位待清理；提交后清理延迟仍为成功，见 G02 5.11.2。CONFLICT_STATE 保留输入并提示重新载入，不能静默覆盖新配置。

6. 业务规则

  1. 官方默认地址：OpenAI Responses 为 https://api.openai.com/v1；Anthropic Messages 为 https://api.anthropic.com。
  2. 切换协议：Base URL 为空，或等于另一协议的官方默认地址时，替换为新协议的官方默认地址；否则保留用户填写的地址（中转服务通常同时支持两种协议）。模型名保留。切换后清空测试结果和 caps；"鉴权头"只对 Anthropic 显示，"不在服务端保存"只对 OpenAI 显示（S02b），切走时值保留但不生效。
  3. Base URL 校验：必填，去掉首尾空格和末尾 / 后不超过 500 个字符；必须能解析为带主机名的 URL，否则"请填写完整地址，例如 https://api.openai.com/v1"；用户名/密码或控制字符报「地址不能包含登录信息或控制字符」；与协议相反的完整端点报「地址端点与所选协议不符」；带 ? 或 # 部分报「地址里不能包含 ? 或 # 之后的内容」；协议只能是 https，或主机为 localhost、127.0.0.1、10.*、172.16–31.*、192.168.*、*.local 的 http。其他 http 地址报错"只支持 https 地址；http 只能用于本机或局域网"。合法的 http 地址在输入框下方显示琥珀色警告"这是未加密的 http 地址，Key 和内容会以明文传输，只建议在自己的局域网里使用。"Android 需在网络安全配置中允许明文流量（构建配置，见架构文档）。地址拼接规则见 产品设计 6.3，由 modelServices.resolveUrl 实现。
  4. 模型：必填，去掉首尾空格后 1–200 个字符，不做格式校验（以服务商为准）。空时"请填写模型名，或点'从列表选择'"。
  5. API Key：新建时必填；edit 模式且 hasKey = false 时必填；其他 edit 情况留空表示不修改。输入内容去掉首尾空白，如果以 Bearer 开头则去掉这个前缀；中间含空白或换行时报错"Key 中不能有空格或换行，请重新粘贴"；长度不超过 512。空时"请填写 API Key"。Key 只在页面/当前请求必要内存中存在，不写日志、不放进导航参数或全局持久状态；关闭释放引用，切后台隐藏明文。显隐读取返回前需校验页面会话和编辑代次，不能覆盖刚输入的新 Key。
  6. 名称（在 S02b 中编辑）：可空，最多 30 个字。为空时保存为自动名称：主机为 api.openai.com → "OpenAI"，api.anthropic.com → "Anthropic"，其他 → 主机名。自动名称与已有服务重名时依次追加" 2"" 3"；手动填写的名称与其他服务重名时报 DUPLICATE"已有同名的模型服务「{名称}」"。
  7. 默认服务：本页不设"设为默认"开关。第一个保存的服务自动成为默认（G02 5.11），之后在 S15a 中切换。
  8. 改动判断：与进入时的值逐项比较（协议、Base URL、模型、Key 输入框是否非空、S02b 全部字段）；测试结果不算改动。只是点"显示"读出已保存的 Key 不算改动。
  9. 保存后去向：
    • from = 'welcome'：若 onboardingDone 为 false，prefs.set('onboardingDone', true)；导航栈重置为 S03 书架。
    • from = 'd03'：返回打开 D03 的页面，并仅在原页面会话仍有效时继续一次刚才被拦下的 AI 操作（重新进入 useAiAction，此时可能弹出 D01）。
    • from = 'settings'：返回 S15，提示条"已保存"。
    • from = 'error'：返回出错的页面，提示条"已保存，可以重试了"；不自动重试。
  10. Key 不随协议外发：测试和获取列表只向 resolveUrl 算出的地址发 Key，MVP 在原生传输层禁止所有自动重定向（含同源，见 G03 2.1）；按 AI_NETWORK 处理，提示「服务返回了重定向，请填写最终地址」。
  11. 能力记录清空：协议、Base URL、模型任一改动时清空 caps（G03 4.2）。只改名称、最大输出等不清空。服务端能力结果不得把旧请求探测写回新配置，见 G02 5.11.3。

7. 边界情况

  • 粘贴的 Base URL 已经是与所选协议匹配的完整端点（以 /responses 或 /messages 结尾）：原样使用，"实际请求"与输入相同。
  • 粘贴的 Key 前后带引号：不自动去除（可能是 Key 的一部分），测试会返回 AI_AUTH。
  • 测试进行中点保存：先中止测试（结果区清空），再按"没有测试过"处理。
  • 测试进行中返回：中止请求，不弹 D04 以外的提示。
  • edit 模式下修改了 Key 但测试失败后仍然保存：新 Key 覆盖旧 Key，lastTest.ok = false，S15 列表显示"Key 无效，点此修改"（S15 规则）。
  • 删除的是默认服务：服务层把剩余最早创建的服务设为默认；删除最后一个服务后，AI 功能会出现 D03。
  • 从 D03 进入后改为点返回：回到原页面，被拦下的 AI 操作取消，不再提示。
  • App 被杀：草稿不保留；已保存的服务不受影响。

8. 验收要点

  • 引导模式显示"稍后再说"；点击后进入空书架，重启不再显示 S01。
  • 四个示例地址（产品设计 6.3 表）的"实际请求"显示与表中一致；切换协议时官方地址自动互换，自定义地址保持不变。
  • http://192.168.1.5:8080 可保存并显示明文警告；http://example.com 报错不能保存。
  • 新建时不填 Key 不能保存；编辑时 Key 留空保存后，原 Key 仍可用（测试通过）。
  • 粘贴 "Bearer sk-xxx" 后保存的 Key 不含 "Bearer "。
  • 未测试点保存出现"还没有测试连接"；测试失败后点保存出现"连接测试没有通过"；测试成功后保存不弹对话框。
  • 从 D03 进入保存后，回到原页面并继续原来的 AI 操作。
  • 有改动时返回出现 D04；无改动时直接返回。
  • 删除服务经 D02 确认；数据库记录删除后不再可调用，安全槽位删除成功或明确显示待清理并可在解锁后恢复清理（G02 5.11.2）。
  • 任何日志、错误详情（D05）、备份文件中都找不到 Key 原文。
