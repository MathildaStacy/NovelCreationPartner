1. 定位与分层

界面层  screens/          只调用 features 服务，不直接访问数据库、secure 或网络
  │  调用
服务层  features/ + ai/    本文定义的函数。读写数据库、调用模型、执行规则、发出事件
  │
数据层  data/  secure/     SQLite（业务数据）  系统安全存储（API Key）  文件（封面、导出）
  • 除明确标为纯函数的工具外，所有服务函数都是异步函数，成功返回结果，失败抛出 AppError（见第 8 节）；连接测试的网络失败由 TestResult 返回，流式终态以 G03 为准。界面层捕获后按 G01 错误展示规则处理。
  • 业务数据库写操作在一个事务里完成，提交后 emit。事务内部辅助函数接收 tx，禁止再调用 db()。SQLite 与系统安全存储不能共用事务，模型服务采用 5.11.2 的分阶段补偿；不能承诺跨存储整体回滚。
  • 写操作完成后发出事件（第 7 节）。界面通过订阅事件刷新，而不是自己去推测哪些数据变了。
  • AI 不能直接修改正式内容。AI 任务只能调用标为 AI 可调用 的函数，这些函数只产生提议、候选或待审核记录。其余写函数只能由作者的操作触发（第 9 节）。
  • 时间统一用本地时区的 ISO 8601 字符串保存；ID 用 UUID v4 字符串；字数统一按"去掉空白字符后的字符数"计算（countChars，见第 5.13 节）。

4. 通用规则

4.1 回收站

作品、章节、档案条目删除时只写 deleted_at，所有列表默认排除。30 天后由启动流程彻底删除（第 10 节）。彻底删除作品时级联删除其卷、章节、版本、条目、关系、对话、提案、冲突、任务和封面文件。恢复章节时回到原卷中原来的位置（原位置及之后的章节顺延一位）；原卷已不存在时，放入作品的第一卷末尾。恢复作品时 updatedAt 不变，作品回到书架原来的位置。

4.2 章节版本快照

来源何时生成保留
auto 自动离开编辑器时，若正文与最近一个快照不同每章最多 50 个，超出删除最旧的自动快照
finalize 定稿定稿本章时永久
before_ai AI 插入前插入或替换 AI 文本之前每章最多 30 个，超出删除最旧的
manual 手动编辑器菜单"存为版本"永久
before_restore 恢复前恢复某个历史版本之前永久

4.3 章节状态

草稿 新建章节。定稿后变为 已定稿。已定稿的章节正文再被修改（正文与定稿版本不同）时变为 有修改未定稿；改回与定稿版本完全一致时恢复为已定稿。只有 kind = 'main'（正文）可以定稿；番外和草稿不参与记忆提取。

4.4 章节编号

正文章节按"卷顺序 → 卷内顺序"连续编号为第 1、2、3… 章，跨卷连续。番外、草稿不占编号。调整顺序后编号随之变化；档案中"自第 N 章起生效"保存的是章节 ID，显示时再换算成当前编号（chapters.numberOf(chapterId)）。比较"某章时的状态"时按章节在作品中的顺序比较，番外和草稿取它前面最近的正文章节。

4.6 正文格式

正文以纯文本保存：换行统一为 \n，一个换行分隔一段，去掉每段段首的空白（含全角空格），不保存缩进。编辑器显示时每段前加两个全角空格（见 S07）。所有字符偏移（光标、选区、evidenceOffset、findText）都以规范化后的存储正文为准。

4.5 档案状态

五种状态及流转见产品设计文档第 8 节。条目的状态取其字段的"最高"状态：任一字段有冲突 → 有冲突；否则任一字段正文已建立 → 正文已建立；否则任一字段已确认 → 已确认；全部为提议 → 提议。作者手动废弃整个条目时为已废弃。

5.11.2 SQLite / 安全存储补偿

  1. 新增或替换 Key：校验后生成新 keyRef，先用短事务登记 credential_cleanup，再写入并读回确认新安全槽位。绝不覆盖旧槽位。随后一个业务事务检查 revision，切换 key_ref/has_key、保存配置/默认值/recentModels，从清理表移除新引用、加入旧引用。成功提交后 emit，再清理旧槽位。
  2. 失败或杀进程：业务事务未提交，旧配置和旧 Key 仍有效；新槽位由清理记录回收。安全写入失败可能已留下槽位，也保留清理记录。清理失败不删除登记，不把原失败改成成功。事务已提交但旧 Key 删除失败，save 返回成功且 keyCleanupPending=true，不回滚新配置。
  3. 留空编辑：不读写旧 Key 即可保存其他配置，临时锁定不阻止这种保存；没有 key_ref 的服务必须补 Key。has_key 仅是存在性元数据，不代表 Key 可读或鉴权有效；确认槽位缺失时，比较原 key_ref 后事务置 has_key=0、key_ref=null、lastTest=null 并递增 revision/emit，随后网络操作报 KEY_UNAVAILABLE。暂时锁定不做该修正。
  4. 删除：中止该服务全部在途请求，业务事务删除服务、选继任默认、登记旧 key_ref；提交后 emit，再幂等删除安全槽位。数据库失败不删 Key；提交后安全删除失败返回 keyCleanupPending=true，服务已不可再选，请求迟到结果不能写回。提示「服务已删除，设备解锁后继续清理本机 Key」，不能报「整个删除失败、记录保留」。
  5. 恢复清理：启动后、App 回到 active 时及后续服务写操作后重试清理；与保存共用协调锁。只删除清理表中且不被 model_services 引用的槽位，确认删除成功后事务移除登记。被引用的槽位绝不删除。锁定或清理错误不阻塞离线写作；S15 保留「本机 Key 待清理」提示（通过 features 的 modelServices.hasPendingKeyCleanup() → boolean 查询）。不做周期轮询。

这是跨存储所需的最小持久化补偿记录，不建立通用任务框架。所有数据库变更（包括准备/清理）分别放入短事务，安全存储和网络等待不放在 SQLite 事务内。业务成功事件只能在对应业务提交后发出；清理状态变化可额外发 services.changed。Key/掩码/Key 哈希不进入 SQLite、备份、日志或测试样本；测试用运行时生成的无效临时值。JS 字符串不能保证物理擦除，只承诺及时解除引用、不持久化。

6. 后台任务队列

  1. 来源与确认：只有作者确认 chapters.finalize 的不可变预览或 conflicts.recheck 会入队。同一 planId 重复确认返回既有任务，不创建第二批请求。
  2. 顺序：全局前台串行；同 operationId 按 summarize → extract_memory → detect_conflicts 顺序。前序未完成时后续保持 queued；取消 extract_memory 允许同作业检测继续，取消摘要由 S05b 明确确认后取消同作业未完成任务。
  3. 使用的模型：预览时按作者 utility / review 绑定解析服务，无显式绑定才使用当时默认；确认时固定服务 ID/revision 与请求内容。旧任务不随切换默认或偏好更新换服务。缺绑定或已删除服务在 claim 时暂停 no_service，服务版本/输入失效暂停 stale；须重新预览并确认定稿。
  4. 暂停原因（Job.pauseReason）：no_service（无有效绑定）、no_key（绑定服务 hasKey=false）、notice（绑定域名未确认 D01）、interrupted（取消/网络/超时/流中断或崩溃后当前未完成块存在尝试记录）、legacy_input（旧任务无绑定输入）、stale（定稿/本地依赖/服务版本已失效）、budget（请求、输出或期限不足）、batch（等待作者授权下一批）。offline 为兼容类型，当前没有网络状态订阅或自动联网恢复。领取前暂停不增加 attempts；领取后发生暂停仍保留本次执行计数及物理账本。
  5. 恢复与重试：services.changed 和回到 active 只唤醒执行器检查 queued，不把 paused 自动改回 queued。作者在 S05b 确认 D01、处理绑定服务 Key 后显式调用 resume；修改服务 revision 后旧计划失效，需重新定稿。interrupted 额外确认可能再次计费。仅无输出且可重试的限流/服务错误可在当前请求内退避重试；网络/超时/流中断不自动重发。每块最多 3 次，全部重试和参数降级共享整作业 N+2 次 POST、输出预留及原期限，手动恢复也不清零。
  6. 前后台：App 退到后台中止当前请求；runner 保守记为 paused/interrupted（依赖已失效则 stale），不直接回 queued。回到前台只处理尚在 queued 的安全任务；中断项等待作者确认。V1 不使用系统后台执行。
  7. 启动恢复：先恢复尝试账本，再按 recoverRunning 检查当前首个未完成块。即使不能确认是否已到达服务端，有尝试预留记录也保守暂停 interrupted；只有无当前块尝试记录、绑定和依赖仍有效时自动回 queued。已校验完成块复用检查点，不重发；旧输入、服务缺失或依赖过期均保持暂停。
  8. 取消与覆盖：重新定稿取消未完成旧任务并撤销旧 token；已完成任务仅在完整依赖匹配时复用。删除章节取消相关任务；作品软删后队列跳过，运行中的提交校验拒绝旧结果。恢复作品不绕过版本、依赖、服务、暂停原因或已用预算校验。
  9. 预算与进度：确认前展示整作业 N 个未缓存请求块、最多 N+2 次物理请求、估算输入和总输出预留；费用未知保持未知。超过 6 个待发送块时先展示完整范围与消耗，作者可仅保存定稿或显式授权首批最多 6 块；未授权块暂停 batch，后续由 S05b 预览并确认连续下一批。所有批次共享原父预算和期限；单段过长或无法保留必要上下文才暂停 budget，要求拆章重新预览。S05b 显示已验证块数与全部块数、父预算和未知用量，未全部完成不称完整整理或审核。
