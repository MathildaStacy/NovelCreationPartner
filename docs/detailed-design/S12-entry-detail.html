1. 页面功能

  • 头部显示名称（宋体）、类型、条目状态、别名。
  • 按类型的字段模板显示字段；每个字段显示自己的状态、出处和生效章节；空字段显示"未填写"，点一下去填写。
  • AI 的提议字段以虚线框显示，逐条采纳或丢弃；对已有内容的提议显示为"原值 → 新值"。
  • "按章节的状态"时间线：看一个人物或设定在哪一章发生了什么变化；切换"查看第 N 章时的状态"，不用当前状态覆盖过去。
  • 关系列表，添加和编辑关系。
  • 出场章节：用名称和别名在正文中搜索，点一章跳到第一次出现处。
  • 冲突和待审核变更的提示与入口。
  • 伏笔：手动标记已回收 / 未回收。
  • 菜单：让 AI 补全、版本历史、废弃 / 恢复、删除。

5. 数据与本地服务

进入页面

  • 调用 entries.get(entryId)，得到条目、当前有效字段、待定提议、时间线、关系、未处理冲突、待审核提案。
  • 随后单独计算出场章节（不阻塞页面显示）。
  • 路由参数 highlightFactIds（从 S12c 返回时带入）：渲染后高亮这些提议并滚动到第一条。
需要新增：chapters.findText(workId, terms: string[], { kinds: ChapterKind[] }) → { chapterId, number, kind, title, count, firstOffset, firstLength }[] —— 在章节正文中查找名称和别名（最长匹配优先、不重叠计数），返回每章出现次数和第一次出现的位置，用于"出场章节"和跳转到 S07 时定位。entries.get 中的"出场章节"也应由它计算。
需要修改：entries.get 的返回值需要明确：每个字段的 sourceLabel 与出处（章节 ID、原句）、伏笔的回收状态、时间线节点 { chapterId, number, field, value, kind: 'fact'|'pending', factId?, proposalId? }。

订阅事件

  • entries.changed（entryIds 含本条目或其关系对象）：重新调用 entries.get，保留滚动位置和"查看第 N 章"的选择。
  • proposals.changed：刷新待审核提示和时间线待审核节点。
  • conflicts.changed：刷新冲突提示和徽标。
  • chapters.changed、chapter.saved：章节编号或正文可能变化，刷新章节编号显示，重新计算出场章节（chapter.saved 合并为 5 秒内最多一次）。

6. 业务规则

  1. 条目状态按 G02 4.5 由字段状态汇总；作者手动废弃整条时为已废弃。
  2. 字段状态徽标：已确认是默认状态，不显示徽标；正文已建立、有冲突显示徽标；提议用虚线框表示，不再加徽标。字段有待审核提案时，在徽标位置后加琥珀小点。
  3. 当前值：字段有多个生效区间时，"当前状态"显示生效章节最大、且未结束的那一个；没有生效章节（设定层面始终有效）的值排在所有章节值之前。
  4. 查看第 N 章时的状态：显示 fromChapter ≤ N 且（toChapter 为空或 ≥ N）的值；没有生效章节的值始终显示。只计算已生效的值，不含提议和待审核。关系同样按区间过滤。只能选正文章节。
  5. 时间线节点：每个有生效章节的已生效值一个节点，加上每条带章节的待审核提案一个节点；按章节编号升序，同一章内按字段模板顺序。编号随章节顺序调整而变化（G02 4.4）。
  6. 出场章节：搜索词为名称和全部别名；长度为 1 个字的名称或别名不参与搜索（避免误匹配），此时在标题旁说明"单字名称不参与统计"。范围为正文和番外章节，不含草稿和回收站中的章节。同一处文字只计一次，优先匹配更长的词。
  7. 出处：正文已建立的字段显示审核时的章节；章节已删除时显示"（已删除的章节）"且不可点。来源为 AI 伙伴的字段不显示链接。
  8. 伏笔回收：没有 resolved 字段时视为未回收。在本页切换时不设置回收章节；回收章节在 S12a 中设置。切换会产生新的字段版本，可在 S12d 中看到。
  9. 提议高亮：brandTint 背景 2 秒后 300 ms 淡出；页面滚动到第一条高亮提议，使其位于屏幕上 1/3 处。
  10. 字段值按原文显示，保留换行；不做 Markdown 渲染。

7. 边界情况

  • 同一字段同时有修改提议和待审核提案：两者独立显示；先采纳的生效，另一个按新的当前值重新显示为"原值 → 新值"。
  • 查看第 N 章时，后台任务写入了新数据：仍停留在第 N 章视图，数据按事件刷新。
  • 查看第 N 章后，第 N 章被删除或改为番外：自动回到当前状态，提示条"第 N 章已不存在，已回到当前状态"。
  • 关系对象已被删除（在回收站）：关系随对象一起隐藏。
  • 从关系进入另一条目、再从那里进入回来，形成很深的页面栈：不限制层数，系统返回逐层返回；"档案"标签再次点击时回到 S11 根页面。
  • 条目有 300 个以上出场章节：默认仍只显示前 3 章，展开后列表虚拟化。
  • 采纳提议的同时该字段的冲突被处理：以后到者为准，界面按事件刷新。
