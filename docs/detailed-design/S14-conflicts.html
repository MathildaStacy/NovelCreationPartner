1. S14 · 冲突列表页功能（#s14）

  • 三态筛选与章节过滤：支持切换待处理 (open)、稍后处理 (later)、已处理 (fixed_text / updated_entry / intentional)。若从某章节（S06 或 S07）带 chapterId 进入，顶部显示过滤胶囊筛选：第 N 章 ×（可点 × 查看全书冲突）。
  • 排序规则：按严重程度（high 高 → medium 中 → low 低）优先，同级别按发现时间倒序。
  • 重新检查冲突：点击右上角重新检查，选择一个当前已定稿的正文章节（优先当前章节，否则最近定稿）。调用 conflicts.prepareRecheck(chapterId) 生成本地不可变计划，先展示整个操作的服务、请求数、重试/格式修复共享上限、输入估计、输出预留和未知费用；作者可查看每块完整请求。作者确认且完成 D01 后，将同一份计划传给 conflicts.recheck(chapterId, plan) 入队 detect_conflicts，不重复摘要或提取。

4. 数据与本地服务

  • conflicts.list(workId, { status })：分段数据；已处理分段传 fixed_text / updated_entry / intentional，带章节筛选时在本地按 chapterId 过滤。
  • conflicts.prepareRecheck(chapterId)：仅在本机生成 FinalizationPreview，只含 detect_conflicts；conflicts.recheck(chapterId, plan)：验证正文版本、设定依赖、服务版本和任务策略后原子入队，提交后发出 jobs.changed。
  • 监听 conflicts.changed、jobs.changed 刷新列表、分段计数和顶部状态条。

5. 业务规则

  1. 排序：严重程度 高 → 中 → 低，同级按发现时间倒序。
  2. "稍后处理"的冲突仍计入 S06 冲突徽标、S07 冲突提示条和 S05 待处理计数；只有已处理（改正文 / 更新档案 / 有意为之）才减少计数。
  3. 重新检查只入队后台任务，不阻塞页面；与已标记有意为之的冲突相同 fingerprint 的结果被丢弃，与 open 冲突相同的更新而不新增（G02 5.9）。
  4. 本页只读列表，所有处理在 S14a 完成，均为本地操作。

6. 边界情况

  • 冲突所属章节或条目被删除：冲突随之隐藏，不计入角标；从回收站恢复后重新出现。
  • 重新检查时未绑定模型或缺少 Key：展示明确原因并引导配置，返回后需要重新预览；不自动续发。正文、设定、策略或服务在预览后变化时拒绝旧计划。
  • 从 S14a 处理后返回：列表已随事件刷新，被处理的卡片移到对应分段。

7. 验收要点

  • 在 S07 编辑器点击顶部冲突提示条：若本章仅 1 处冲突，直接打开 S14a 详情；若多于 1 处，打开 S14 并自动按本章过滤。
  • 标记为"有意为之"的冲突，对该章再次执行"重新检查"后不会再次弹出报警。
  • 冲突解决后，关联人物条目详情页上的"⚠ 有冲突"红色徽标同步消失。

当前界面实现 · 2026-10-18
