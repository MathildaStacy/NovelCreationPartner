1. 页面功能

  • 显示 App 名称、版本号和构建号，便于反馈问题时提供。
  • 隐私说明：本地优先、无登录、无后端，数据只发往作者自己的模型服务。
  • 满足 GPL-3.0-only 的告知义务：显示许可证名称与全文、源代码地址；列出第三方开源组件及其许可证。

4. 数据与本地服务

  • 不读写数据库，不调用 G02 业务服务，不联网（打开链接交给系统浏览器）。
  • 版本号：原生模块读取（如 react-native-device-info 的 getVersion() / getBuildNumber()）。
  • 许可文本：构建时把仓库 LICENSE 复制为 App 资源。
  • 第三方清单：构建脚本扫描生产依赖（package.json 的 dependencies 及其传递依赖，含 React Native、SQLite、Keychain/Keystore、分享、文件选择等原生库），生成 third-party-licenses.json（名称、版本、许可证、许可文本）打包进 App；不在代码中手写清单。开发依赖（eslint、jest 等）不列出。

5. 业务规则

  1. 许可证表述：一律写"GPL-3.0-only"，不写"GPL-3.0 或更高版本"。
  2. 隐私说明须与实现一致：
    • 数据存储在本机 SQLite 数据库和 App 沙盒文件中；没有登录、账号或云同步；App 本身不连接任何开发者服务器，不含统计、广告或崩溃上报 SDK。
    • 只有作者使用 AI 功能时，按 D01 说明的范围，把内容直接从手机发送到作者配置的模型服务地址；服务商如何处理数据由其政策决定。
    • API Key 存于 iOS Keychain / Android Keystore，不写数据库、不进备份、不导出。
    • 导出和分享只在作者主动操作时发生（S15b）。
  3. 第三方清单的许可证兼容：清单生成脚本发现与 GPL-3.0 不兼容的许可证（如 GPL-2.0-only、专有许可）时构建失败，需人工处理。
  4. 无更新检查：MVP 不联网检查新版本，更新由 App Store / 应用市场负责。

6. 边界情况

  • 开发构建：版本后加"（开发版）"，第三方清单可能为空，此时子页显示"开发构建未生成许可清单"。
  • 许可证全文很长：子页自身滚动，使用虚拟化文本或分段渲染避免卡顿。
  • 系统深色模式：MVP 跟随全局主题处理，本页无特殊规则。

7. 验收要点

  • 版本号与构建号与安装包一致；点按后剪贴板内容正确。
  • "开源许可"子页显示 GPL-3.0-only 中文摘要与 LICENSE 全文，飞行模式下可打开。
  • 第三方清单包含全部生产依赖（至少 React Native 及所用原生库），每项有许可证名称和文本；不含开发依赖。
  • 隐私说明文案与示意一致，抓包确认打开本页和 App 空闲时无任何网络请求。
  • "源代码""反馈问题"用系统浏览器打开正确地址。
