## 本轮设计的核心决定

完整设计在 [G04 AI 成本与效果](../detailed-design/G04-ai-efficiency.html)，总图在 [技术架构 v2.1](../architecture/index.html#efficiency)。G04 明确列出的修订替代旧 G03 的相应条款；其余 G01–G03、S/D 页面继续生效。G04 列出实施时需要同步的接口、迁移和页面，不能只改代码留下两套矛盾契约。

目标是降低每次可用、被采纳结果的总费用，同时守住事实和作者意图。先做本地检索、精准上下文、请求去重、统一尝试预算和逐次用量账本；再做缓存适配与可选任务服务绑定。新用户默认一个候选，保留已有显式偏好；保留深度一致性检查的质量预算。

## Sol 开发顺序与完成条件

### A. 档案本地闭环（立即开始）

读取 G02 §5.5/5.6、G03 §6.0、S11、S12、S12a/b/d、S07c，结合现有 types/chapters/versions/trash/maintenance。实现 entries/relations、字段版本与按章取值、FTS5 trigram 及短查询 LIKE、迁移、历史/关系/编辑/查阅 UI 和导航。保留 G02 事务语义和跨模块的 tx helper。

验收重点：中文短名与别名、字段按章生效、章节重排、跨作品 ID 拒绝、删除/恢复、同名冲突、历史恢复、FTS 更新/删除一致、数据库升级保留现有写作和模型服务。S12c AI 补全留给 E，未完成的入口须诚实说明。先检查是否有作者新提供的档案提交；有则集成核对，不盲目重写。原生网络 gate 不阻塞此离线阶段。

### B. AI 公共基础 + 第一条可用写作链路

按 G04 实现最小 TaskPolicy / ContextPlan / RequestBudget / AiAttemptLedger，以及 D01、features AI 门面、S08/S09 describe/quickEdit、插入与撤销/恢复。先支撑这两个任务，不一次性生成尚无调用方的框架。schema/Types 更新对应 G02/G03，S08/S15e 的新用户候选默认值改为 1，已有显式偏好不变。

完成条件：本地 preview 与实际请求同一份不可变 ContextPlan；明确参考设定不被静默裁剪；关闭弹窗/停止不再重发；所有 POST 有总上限；重试、失败、取消也进账本；AI 不直接改正文，插入校验编辑会话与内容版本，先保存 before_ai 快照；离线写作不受影响；首次作品外发经过 D01。

缺少设备或凭据时完成可独立实现和测试的部分并记录缺口，不使用 Mock 宣称真实调用成功，不因缺少原生结果阻塞全部开发，不默认调用真实收费服务。原生已知失败则先修原因，不能绕过禁重定向或放宽全局明文策略。

### C. 伙伴与结构化采纳

实现 conversations、S10–S10e、结构化验证、方案对比、采纳/暂存/撤销。本地保存明确决策；对话历史压缩不把提议升级为事实。默认一次生成，对比和拆解仅按作者操作触发；正文已生成后的 JSON 格式失败不整段重发。

### D. 定稿任务与记忆闭环

先补版本绑定、attempt ledger、依赖 revision、旧任务迁移和崩溃恢复，再启用 runner。实现 summarize → extractMemory → detectConflicts、S05b、S13/13a、S14/14a。重新定稿只复用满足全部依赖指纹的派生结果；删除/纯删除 diff 不能静默跳过；摘要不代替提取证据。未知是否已计费的中断请求不自动重放，历史未绑定版本的任务不因配置服务就自动执行。

完成条件：旧定稿/删除后的迟到结果不能写入；重复任务不重复生成提案；无证据内容不成为正式设定；「有意为之」正确去重；分块任务执行前展示和限制整个作业费用，避免每块各自重试扩大开销。

### E. 效果完善与剩余 MVP

完成 S12c AI 补全、可选任务服务绑定与轻量用量展示、S01、S15b–f、导出恢复/回收站，再完成双端整体验收。厂商显式 prompt caching 按证据启用，不能成为基础链路前置依赖；向量检索、自动语义评审、服务端编排和 Batch 本轮不引入。
