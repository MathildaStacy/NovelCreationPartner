0摘要

本文是全应用的技术架构总图。G02 本地服务层、G03 AI 调用与任务和各 S/D 页面是实现契约；本轮明确修订的成本、上下文与恢复规则以 G04 §2为准，其余沿用原契约。图中的 TaskDef、Retriever、Executor 等是目标形态，不代表已有代码；实际完成情况见最新交接。

本地即事实源

SQLite 是唯一业务事实源，安全存储只放 Key，文件只放封面和导出。界面不缓存第二份真相，写后由事件驱动重读。

六层单向依赖

App 壳 → 表现 → 领域服务 → AI 运行时 → 基础设施端口 → 原生平台。只能向下调用，向上只通过事件和回调。

端口与适配器

数据库、安全存储、HTTP 传输、时钟、文件都是接口；设备上接 op-sqlite / Keychain / 原生 TurboModule，测试里接 node:sqlite 与内存实现。

AI 是可插拔运行时

调用管道 → 任务注册表 → 上下文组装 → 协议适配器 → 原生传输，五段解耦。新增协议或新增 AI 任务都不改动已有任务。

AI 只能提议

AI 代码只能导入“AI 可调用”的写函数，正式档案和正文只能由作者操作改变。由 ESLint 边界规则和自动化测试双重守护。

为同步与后端留门

变更日志、执行器端口和检索端口是预留扩展点：今天全部在本机实现，将来可接端到端加密同步与 LangGraph 服务端编排，而不改领域层。

1目标与质量属性

产品的核心承诺是“正文零丢失、设定不被 AI 偷改、断网照样写、Key 不离开手机”。架构按质量属性逐项落实：

质量属性可度量目标架构手段
数据安全任何崩溃、杀进程、断电下不丢失已停顿 2 秒的正文；AI 改动可回滚单事务写 + 写前快照（G02 §4.2）；编辑器自动保存会话；迁移前向且每版有升级测试
隐私与密钥Key 不出现在 SQLite / WAL / 备份 / 日志 / 导航参数中随机槽位引用 + 清理登记补偿（G02 §5.11.2）；日志白名单；原生层禁重定向、禁 Cookie 与缓存
离线可用除模型调用外 100% 离线无业务后端；AI 失败只影响 AI 卡片；本地定稿独立成功；AI 中断保守暂停，作者确认后沿用原预算恢复
响应性本地查询 <16ms 不闪加载态；5 万字章节输入不卡顿；流式首字即显JSI 同步驱动 op-sqlite；列表不读正文；事件 300ms 防抖重读；流式 AsyncIterable
正确性每个逻辑 AI 请求只有一个终态；迟到结果不写库请求所有者 + AbortSignal 树 + 请求代次；事务内 revision 校验
可扩展新增协议 / AI 任务 / 导出格式主要修改对应模块和组合入口小接口、纯函数与有限注册表；有第二个真实实现时再抽象；不承诺跨端扩展零改动
可测试领域与 AI 逻辑在 Node 中可测，无需模拟器端口注入；时钟与 ID 可替换；协议样本回放；故障注入
可演进引入同步或服务端执行时领域层不重写变更日志、执行器端口、检索端口（第 11–12 节）

2架构原则

  1. 契约先行。服务函数名、参数、事件、错误码以 G02/G03 为准；实现与设计不一致时先改设计，再写代码。
  2. 单向依赖。上层只调用下层公开接口；下层通过事件或回调通知上层，绝不导入上层。
  3. 一个事实源。持久状态只在 SQLite；Zustand 只承载界面瞬时状态（浮层、编辑会话），不复制业务数据。
  4. 提交后才广播。写操作在一个事务内完成，提交成功后 emit；订阅者永远读不到半写状态。
  5. 跨存储不假装原子。SQLite 与安全存储之间用“登记—写入—切换—清理”的持久补偿，不承诺跨存储回滚。
  6. 取消是一等公民。所有网络与 AI 调用必须接收 AbortSignal；页面释放、配置变化、删除都会中止并丢弃迟到结果。
  7. AI 只产生提议。AI 产物进入提议、候选、待审核表；正式写入只由作者事件触发。
  8. 可观测但不泄密。日志只记录白名单字段（任务名、协议、错误码、状态、耗时、长度），从不记录正文、请求体与 Key。
  9. 平台差异收敛在最底层。Android/iOS 差异只出现在原生模块和驱动里，JS 层只看统一端口。

5.1 模块内部结构（模块解剖）

模块当前是单文件（如 features/works.ts）。单文件超过约 400 行，或出现第二个内部关注点时，拆成目录，对外仍只有 index.ts：

features/entries/
├── index.ts        // 公开 API：只导出 G02 列出的函数与类型（含“AI 可调用”标记）
├── service.ts      // 公开函数实现：校验 → db.transaction → emit
├── queries.ts      // 只读 SQL 与行映射；按章取值（atChapter）
├── tx.ts           // 接收 tx 的内部辅助函数，供本模块与同事务调用方使用
├── rules.ts        // 纯函数：状态取最高、重名判定、生效区间切分
└── types.ts        // 行类型 ↔ 领域类型

约定：公开函数不接收 tx；接收 tx 的函数不调用 db()，也不 emit；事件由最外层公开函数在提交后统一发出。

5.2 表现层的组织

页面目录与设计文档的分组一一对应：shelf/（S03–S04）、work/（S05–S06）、editor/（S07–S09）、partner/（S10）、archive/（S11–S12）、review/（S13–S14）、settings/（S15、S02）、onboarding/（S01）。复杂页面把纯逻辑拆到同目录的无 React 文件（如 editor/autosave.ts、history.ts、diffRows.ts），以便在 Jest 中直接测试。

6.1 启动序列（G02 §10）

失败 → 错误页

失败 → “数据升级失败”

6.2 写路径

界面事件按钮 / 自动保存
领域函数校验输入，失败抛 VALIDATION
一个事务db.transaction(tx => …)
内部辅助只接收 tx
提交串行锁释放
emitG02 §7 事件
订阅者重读useLoad 300ms 防抖

数据库只有一个连接，Db 用串行锁保证同一时刻只有一个事务或语句在执行；事务内嵌套调用加入外层事务。在事务内调用 db() 会等待自己持有的锁而死锁，因此是代码评审的硬性检查项。

6.3 读路径与状态

  • 业务数据：页面通过 useLoad(fn, deps, { events }) 调用服务读取，订阅相关事件后防抖重读；序号保证旧结果不会覆盖新结果。返回页面时可按需重读。
  • 界面瞬时状态：浮层队列、对话框、编辑器会话等放在 Zustand 或组件状态里；不放 Key、不放业务实体副本。
  • 演进：当同一数据被三个以上页面读取时，引入“事件标签查询缓存”——useQuery(key, fn, { tags: ['entries.changed:workId'] })，同一个 key 的并发读取合并为一次，事件按标签失效。它只是读缓存，失效后仍回到 SQLite，不改变单一事实源原则。

6.5 错误模型

原生 / 驱动异常SQLite、Keychain、HTTP

协议归一HTTP 状态 + 服务商错误码 → AI_*（白名单诊断）
领域错误VALIDATION、DUPLICATE、NOT_FOUND、CONFLICT_STATE、NO_SERVICE
展示映射app/errors.ts → 字段 / Toast / 卡片 / 对话框 / D05

7.3 迁移策略

  • 迁移是 src/data/migrations/NNNN_name.ts 中的语句数组，只追加不修改；版本号写入 PRAGMA user_version，每个迁移在一个事务内执行。
  • 每新增一个迁移，增加“从上一版本带数据升级”的测试，断言已有写作数据不丢失（0002 已有此类测试）。
  • 规划中的迁移按功能阶段引入：档案阶段新增 FTS5 外部内容表与触发器；AI 伙伴阶段补齐消息索引；如需同步再新增 change_log。不提前建空表。

7.4 备份格式

.ncpbak 是 zip：manifest.json（格式版本、App 版本、导出时间、作品清单）+ data.json（业务表，排除回收站与凭据元数据）+ covers/。恢复时全部 ID 重新映射为新 ID，只新增、不覆盖；格式版本高于当前支持的版本时拒绝（BACKUP_TOO_NEW）。格式版本号与数据库迁移版本解耦，导出器负责把当前 schema 映射为稳定的备份结构。

8AI 运行时

AI 能力是一套分段的运行时，而不是散落在页面里的网络调用。每一段只知道自己的输入输出，因此可以分别测试、分别替换。

① 调用方页面 useAiAction() 或后台 runner
② 调用管道网络 → 服务 → D01 数据说明 → 读 Key（G03 §1）
③ 任务ai/tasks/* 声明默认参数、上下文层级、提示词、Schema、写入去向
④ 上下文组装8 级优先级、token 估算、预算裁剪；与 previewContext 同一函数
⑤ 编排器逻辑请求期限、有限重试、能力降级、caps 回写
⑥ 协议适配器Responses / Messages：组请求、解析 SSE / JSON、错误归一
⑦ 原生传输禁重定向、无 Cookie / 缓存、增量字节、abort

8.1 任务注册表

9 个业务 AI 任务按需声明定义；连接测试与模型列表是已有基础设施能力。新增任务复用管道、预算与适配器，不为尚无调用方的能力预建完整框架。以下为目标形态。

// ai/tasks/types.ts（目标形态）
export interface TaskDef<In, Out> {
  name: 'ideate' | 'describe' | 'quickEdit' | 'compareOptions' | 'splitForAdoption'
      | 'completeEntry' | 'summarizeChapter' | 'extractMemory' | 'detectConflicts';
  stream: boolean;
  defaults: { maxOutputTokens: number; effort: 'low' | 'medium' | 'high' };
  context: ContextLayer[];                        // G03 §5.2 的 1–8 级中本任务使用哪些
  prompt: { id: string; version: number };       // ai/prompts/{id}.v{version}.ts，版本随用量记录
  schema?: JsonSchema;                            // 有则走 G03 §4 三级降级
  build(input: In, ctx: AssembledContext): GenerateRequest;
  parse(result: TaskResult): Out;                 // 本地校验、截断、匹配 targetEntryId
  // 只返回校验结果；features 负责版本校验与受限的业务事务写入。
}

8.2 协议适配器注册表

适配器只处理“配置快照 + 一次物理请求”，不访问业务库、不自行重试（G03 §2.2.0）。当前代码通过 createProvider 按协议分支；下列注册表是增加协议后的可选演进，不是已实现 API：

registerProvider('openai_responses',   createOpenAIResponses);
registerProvider('anthropic_messages', createAnthropicMessages);
// 以后新增协议（例如 Chat Completions 或其他厂商）只新增适配器与 resolveUrl 规则，
// 并在 S02 协议选择中出现；任务、上下文与编排器保持不变。

能力（caps.jsonSchema / effort / streaming）是“按服务探测、带证据才写入”的事实，而不是按模型名硬编码；这让自定义网关和新模型无需发版即可使用。

8.3 流式与终态

  • 适配器返回 AsyncIterable<StreamEvent>：text 增量、唯一终态 done / error / cancelled。界面用 useStream 消费，停止即 iterator.return()。
  • 传输层输出原始字节块，Utf8Decoder 有状态解码，SSE 解析器只保留未消费尾部；单帧 1 MiB、总量 16 MiB 上限。
  • 期限：首字节 60 秒、空闲 90 秒、单个逻辑请求/定稿请求块 5 分钟；定稿父作业在首次可执行领取后启动 min(5N,30) 分钟期限，每块从首次尝试起算，不因恢复重置。测试与列表 20 秒总期限。计时包含后台挂起时间。

8.4 后台任务执行器

定稿后的摘要、记忆提取、冲突检测由 App 内单执行器串行运行，状态与定稿版本、服务 ID/revision、完整依赖及父预算持久化；每块 checkpoint，重启按当前未完成块的尝试记录恢复。服务配置变化和联网不会自动重排 paused，中断可能计费须作者确认（G02 §6）。

转换触发
queued → runningApp active、单执行器空闲；同作业前序已完成（取消提取可继续检测），版本/依赖/服务快照、Key、D01 和父预算有效；claim 生成 token 并增加一次执行计数

paused / failed → queued作者显式 resume，先核对原输入与服务；interrupted 需确认可能重复计费。已用请求/输出/期限不清零；legacy_input、stale、budget、no_service 从界面引导重新预览定稿。batch 仅经原请求预览和作者逐批授权恢复，共用原父预算和期限；services.changed / active 只唤醒 queued，网络恢复无自动重排
后台中止 / 启动恢复退后台 abort，runner 保守暂停 interrupted；启动时当前首个未完成块有尝试记录就 interrupted，无当前块记录且绑定/完整依赖有效才回 queued，已验证块不重发。旧输入、服务缺失或依赖失效保持暂停
未完成 → cancelled作者取消、重新定稿、删除章节并撤销 token；S05b 取消摘要经确认后逐项取消同 operationId 未完成任务，已完成结果保留

当前本机入口为 features/finalizationRunner.runNext(signal) / drain(signal)，由前台 app/jobQueue 驱动；发送持久化原 ContextPlan，经 jobs 的 token/版本/依赖守卫提交。Executor 远程端口仍为可选演进（§12），本轮未引入。
