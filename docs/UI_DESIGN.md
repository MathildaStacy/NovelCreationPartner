本文规定视觉语言、组件和页面布局。页面的功能和规则以[产品设计文档](PRODUCT_DESIGN.md)为准，页面编号 S01–S15 两边一致。

## 1. 设计方向

第一版草图已经定下了基调：浅色界面、紫色品牌、书本形状的标志、偏幻想的气质。本版保留这些，并做了三项收紧：

1. **让界面像一张稿纸，而不是一个聊天机器人。** 正文占据最大的空间，AI 只在作者召唤时出现。
2. **把"AI 提的"和"作者定的"做成一眼能分辨的视觉语言。** 这是本产品与通用写作 App 最大的区别，也是界面上唯一需要张扬的地方，其余部分保持安静。
3. **去掉不必要的装饰。** 按钮不用渐变，作品不配插画，卡片不叠阴影。

## 2. 设计原则

**虚线是提议，实线是定稿。** AI 生成的设定、选项、描写候选和记忆变更，一律用紫色虚线框，左上角标"AI 提议"。作者采纳、插入或通过之后，边框变成实线，标签改为结果（"已采纳""已插入""已通过"）。全 App 只用这一种方式表达"未确认"，不另造标记。

**宋体是作品的声音，黑体是 App 的声音。** 小说正文、书名、AI 写的描写候选、正文引文用宋体；按钮、标签、说明、AI 对话里的分析用黑体。用户看字体就能分辨哪些是可以放进小说的文字。

**颜色表示状态，不表示操作。** 青色只表示"正文已建立"，琥珀只表示"待审核或进行中"，朱红只表示"需要你处理的问题"。所有按钮都用品牌紫或中性色，"通过"按钮也不用绿色。

**朱红是编辑的朱批。** 它只出现在两种地方：设定冲突，以及需要你修正的错误（如 Key 无效）。不用于删除按钮，也不用于装饰；看到朱红，就意味着有一处需要你动手。删除等危险操作用确认弹窗把关，按钮本身保持中性。

**状态从不只靠颜色或线型表达。** 每个状态都同时有文字（徽标）和图形（线型或图标），色弱用户和读屏用户都能分辨。

### 3.2 字体

不内置字体，使用系统字体，安装包不增加体积。

| 角色 | iOS | Android | 用途 |
| --- | --- | --- | --- |
| 黑体 `sans` | PingFang SC（系统默认） | 系统默认（Noto Sans CJK） | 界面文字 |
| 宋体 `serif` | Songti SC | `serif`（多数设备为 Noto Serif CJK） | 正文、书名、描写候选、引文 |

少数 Android 厂商系统没有中文宋体，会回退为黑体，功能不受影响。若用户反馈集中，P1 再评估内置思源宋体（SIL OFL 协议，需要做字符子集控制体积）。

**字号阶梯**（单位 pt / dp，行高写在斜线后）：

| 令牌 | 字体 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| `display` | 宋体 | 34 / 44 | 常规 | 首次启动竖排标语 |
| `title1` | 黑体 | 26 / 34 | 半粗 | 根页面大标题（我的书架） |
| `title2` | 黑体 | 20 / 28 | 半粗 | 弹窗标题、作品名 |
| `headline` | 黑体 | 17 / 24 | 半粗 | 导航栏标题、卡片标题 |
| `body` | 黑体 | 15 / 22 | 常规 | 正文以外的主要文字 |
| `callout` | 黑体 | 13 / 18 | 常规 | 辅助说明、列表第二行 |
| `caption` | 黑体 | 12 / 16 | 常规 | 时间、计数、徽标 |
| `manuscript` | 宋体 | 18 / 34 | 常规 | 章节正文，段首缩进 2 字，段间距 8 |
| `prose` | 宋体 | 16 / 28 | 常规 | 描写候选、正文引文、条目里的设定原文 |

规则：

- 字重只用常规（400）和半粗（600）两档。
- 支持系统字体缩放，上限 1.3 倍（React Native 的 `maxFontSizeMultiplier`）。正文字号另由"写作偏好"控制，可选 16 / 18 / 20。
- 中文不使用斜体。强调用半粗或品牌色，同一段落最多一处。
- 数字使用等宽数字（`fontVariant: ['tabular-nums']`），用于字数、计数和时间。

### 3.3 间距、圆角、阴影

**间距**：4 的倍数，常用 4、8、12、16、20、24、32。页面左右边距 20；卡片内边距 16；列表行高不低于 56。

**圆角**按层级区分，不全部相同：

| 元素 | 圆角 |
| --- | --- |
| 书封 | 3（像真的书） |
| 输入框 | 10 |
| 卡片、主按钮 | 12 |
| 底部弹窗 | 20（仅上方两角） |
| 徽标、筛选标签 | 全圆角 |

**阴影**：只有浮在内容上方的元素有阴影，即底部弹窗、悬浮按钮、选区操作栏，统一为 `0 8 24 rgba(29,26,43,0.12)`。卡片用 1px `line` 描边区分，不加阴影。

### 3.4 图标

线性图标，24×24，线宽 1.75，圆角端点。实现建议使用 `lucide-react-native`（ISC 协议，基于 `react-native-svg`）。图标颜色跟随文字色。纯图标按钮必须设置无障碍标签（`accessibilityLabel`）。

### 3.5 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 底部弹窗出现 / 收起 | 280 / 220 ms | ease-out / ease-in |
| 虚线变实线（采纳、通过） | 200 ms | ease-out，伴随轻触觉反馈 |
| 页面转场 | 系统默认 | — |
| 流式输出 | 文字逐段出现，末尾显示品牌色光标（1 秒闪烁） | — |

系统开启"减弱动态效果"时：弹窗改为淡入淡出，光标不闪烁。

## 4. 组件

### 4.1 按钮

| 类型 | 样式 | 用途 |
| --- | --- | --- |
| 主按钮 | `brand` 填充，白字，高 48，圆角 12 | 每屏最多一个：保存、开始创作、生成 |
| 次按钮 | 白底，1px `brand` 描边，品牌字 | 测试连接、修改后通过 |
| 小按钮 | 高 32，圆角 8，主 / 次两种 | 卡片内操作：通过、采纳为设定 |
| 文字按钮 | 无底色，`brand` 或 `ink2` 字 | 稍后再说、拒绝、换一批 |
| 图标按钮 | 44×44 点击区域 | 导航栏、工具栏 |

文案用动词说明结果：写"保存""插入到光标处"，不写"确定""提交""下一步"。同一个动作在整条流程里叫同一个名字：按钮叫"定稿本章"，提示就叫"已定稿"。

### 4.2 输入框

高 48，圆角 10，1px `field` 描边，获得焦点时 2px `brand`。标签放在框上方（`callout`，`ink2`），说明放在框下方（`caption`，`ink3`），错误时说明改为 `conf` 色并加图标。

API Key 输入框：等宽字体，默认遮挡，右侧"显示"按钮。保存后只显示末 4 位。

### 4.3 状态徽标

| 状态 | 样式 |
| --- | --- |
| 提议 | 白底，1px `brand` 虚线描边，品牌字 |
| 已确认 | `brandTint` 底，品牌字 |
| 正文已建立 | `estTint` 底，青字 |
| 有冲突 | `confTint` 底，朱字，前置警示图标 |
| 待审核 | `pendTint` 底，琥珀字 |
| 已废弃 | `sunken` 底，`ink3` 字，删除线 |

高 22，左右内边距 8，`caption` 字号，全圆角。

章节状态沿用同一套颜色：草稿用 `sunken` 底；已定稿用青色（本章正文已建立）；定稿后又改过、需要重新定稿的，用琥珀"有修改未定稿"。

### 4.4 提议卡与定稿卡

这是第 2 节第一条原则的具体实现，用于创意选项、描写候选、记忆变更和 AI 补全的档案字段。

- **提议卡**：白底，1.5px `brand` 虚线描边，圆角 12。左上角"AI 提议"标签（星形图标 + `caption` 品牌字）。底部是操作按钮。
- **定稿卡**：采纳或通过后，同一张卡变为 1px `line` 实线描边，标签改为结果（如"已采纳为设定"），操作按钮收起，显示"撤销"文字按钮。卡片原地变化，不跳走，作者能看到是哪一张发生了变化。AI 伙伴里的创意选项采纳后进一步收起为一行（结果标签、标题、撤销），让后面的选项留在视野里。
- **React Native 实现**：使用 `borderStyle: 'dashed'`，四边同时设置。Android 对单边虚线支持不可靠，不要只给一条边设虚线。需在真机上核对虚线效果。

### 4.5 变更卡（记忆审核）

结构自上而下：类型图标与类型名、置信度；"原："（`ink3`，加删除线）与"改为："（`ink`）；正文出处（宋体引文，左侧 2px `line` 竖线，可点击跳转）；操作（通过、修改后通过、拒绝）。待审核时为虚线框；通过后变实线并显示"已通过"。

### 4.6 冲突卡

白底，左侧 3px `conf` 边线（这是唯一允许的单边粗线，用实线），标题前置警示图标。详情页里两处出处上下并排，各带来源标签（如"第 3 章正文""世界观：星辰之力"），中间以"不一致"分隔。

### 4.7 书封

- 比例 3:4，圆角 3，底色为题材色。
- 左上角贴一张竖向题签：`slip` 色底、宋体墨字竖排书名，书名最多 8 字，超出截断。
- 右侧 8px 深色书脊，带 4 道浅色装订线（仿线装书）。
- 封面下方：书名（黑体 `callout` 半粗）、第二行为题材与章节数（`caption`），两项之间用空格分隔，不用中点。
- 用户可替换为相册图片。图片封面不显示题签，书脊保留。

### 4.8 导航

- **书架**：大标题导航栏，右侧搜索和设置图标。
- **作品内**：标准导航栏（高 44）加底部标签栏（高 49，另加安全区）。4 个标签：概览、章节、AI 伙伴、档案。选中项为品牌色图标和文字；概览标签上的角标显示待处理数量。
- **编辑器**：隐藏底部标签栏，底部换成写作工具栏。

### 4.9 底部弹窗

上方两角圆角 20，顶部 4×36 抓手，标题 `title2`。高度按内容，最高为屏幕的 90%。下拉或点遮罩关闭；有未保存的输入时，关闭前确认。

### 4.10 流式文本

候选卡中的文字逐段出现，末尾显示 2px 宽的品牌色光标。生成中卡片底部只显示"停止"。完成后光标消失，显示操作按钮。中断时保留已生成的文字，底部说明原因，并显示"继续生成"。

### 4.11 空状态与错误

- 空状态说明下一步做什么，配一个主按钮，不用插画。例如书架空状态："写下第一句灵感，故事就从这里开始"，按钮"新建作品"。
- 错误说明发生了什么、怎么解决，不道歉，不写"出错了"之类的泛泛之词。技术详情（状态码、服务商原文、request id）折叠在"查看详情"里，可复制。文案对照表见[产品设计文档 6.9](PRODUCT_DESIGN.md#69-错误处理)。

## 5. 页面布局

以 375×812 pt 为基准（原型同尺寸），适配 360–430 宽。平板 V1 沿用手机布局并限制内容最大宽度 680。

| 页面 | 布局要点 |
| --- | --- |
| S01 首次启动 | `night` 背景，少量星点。右上方两列竖排宋体标语"让每一个创意 / 都有故事可写"（`display`），从右往左读。下方是标志与产品名，三行说明（`body`，浅紫字），纸色主按钮"开始创作"，文字按钮"从备份恢复"。 |
| S02 连接模型 | 导航标题"连接模型"。分段控件选择协议；表单依次为名称、Base URL（下方实时显示"实际请求"地址）、API Key、模型（右侧"获取列表"）。下方是测试结果区（成功为青色描边，失败为朱色描边），然后是折叠的"高级设置"。底部固定主按钮"保存"，首次引导时上方多一个"稍后再说"。 |
| S03 书架 | 大标题"我的书架"。筛选标签：全部、连载中、已完结。书封三列网格，列间距 16，行间距 24。右下角悬浮按钮"新建作品"（带文字，不只有加号）。 |
| S04 新建作品 | 大号多行输入框（宋体，因为写的是故事本身），提示语举例；题材横向标签单选；作品名单行输入。主按钮"开始构思"，文字按钮"只创建作品"。 |
| S05 概览 | 顶部 120 高题材色带：左侧小书封，右侧书名（白色宋体 `title2`）与题材、状态。下面依次是：进度条（已写 / 计划章数，总字数）；"继续写作"卡（宋体显示最后一段开头）；"待处理"列表（冲突用朱色图标，待审核用琥珀色图标，后台任务带进度）；档案速览三格（人物、设定、伏笔数量）。 |
| S06 章节 | 卷标题吸顶。章节行：序号、标题（`headline`），第二行是状态徽标、字数和时间，第三行是一行摘要（`ink3`）。右上角"新建章节"。 |
| S07 编辑器 | 导航栏：返回、章节标题（居中）、保存状态（`caption`）、更多。正文区左右边距 24，`manuscript` 字号。选中文字时底部工具栏换成选区操作栏（深色 `ink` 底，白字）：改写、扩写、缩写、润色、补细节、描写，显示已选字数。未选中时底部工具栏为：撤销、重做、描写助手、档案、定稿本章。 |
| S08 描写助手 | 底部弹窗。作用范围说明（"改写所选 65 字"），类型六宫格，风格单选标签，版本数步进器，补充要求输入框，"参考"标签组（可删）。底部说明"只写这一段，不推进剧情，不改变已确认的设定"，主按钮"生成"。 |
| S09 描写候选 | 弹窗内横向翻页的提议卡，页码"1 / 2"。卡内为宋体流式文本。底部操作："替换所选"（主）、"再写一版"、"调整要求"。 |

## 6. 文案规范

- 称呼用户为"你"，界面里不出现"用户"二字。
- 用作者熟悉的词，不用技术词：说"档案"不说"知识库"，说"连接模型"不说"配置 Endpoint"。协议名和 Base URL、API Key 是例外，用户需要照着服务商的文档填写。
- 按钮写动作，提示写结果，两者用同一个动词。
- 数字与中文之间不加空格（"第 3 章"除外，沿用小说排版习惯）；英文、模型名与中文之间加一个空格。
- 不用感叹号，不用表情符号。

## 7. 无障碍

- 文字对比度 ≥ 4.5:1，输入框边框等非文字元素 ≥ 3:1（见 3.1）。
- 点击区域 ≥ 44×44。
- 状态同时用文字和图形表达；读屏时，徽标读出状态名，提议卡读出"AI 提议"。
- 流式输出时不逐字播报，完成后播报"已生成 2 个版本"。
- 支持系统字体缩放（上限 1.3 倍）和减弱动态效果。

### 8.2 实现提示

- **竖排文字**：React Native 不支持 `writing-mode`。书封题签和首屏标语把每个字单独换行排成一列；多列时用 `flexDirection: 'row-reverse'`，让第一列在最右。竖排文字里不放标点。
- **选区**：`TextInput` 的 `onSelectionChange` 只提供字符位置，没有屏幕坐标，所以选区操作放在底部工具栏，不做跟随选区的浮动菜单（与原型一致）。冲突也不在正文里画波浪线，改为顶栏下方的提示条。
- **长文本**：单章正文控制在 2 万字以内的流畅输入，超出时提示分章。编辑器性能需要在中低端 Android 机上实测。
- **安全区**：使用已安装的 `react-native-safe-area-context`。
