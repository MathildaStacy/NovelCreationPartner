# Settings storage usage validation · 2026-10-18

`features/storage.usage()` uses the existing AppInfo native module and accepts no filesystem path. Native `getStorageUsage()` returns only nonnegative byte counts for `db`, `covers`, and `cache`. Android counts the fixed `getDatabasePath("novel.db")` file and its `-wal`/`-shm` siblings, `files/covers`, and the app cache directory. iOS counts `Library/novel.db` and its WAL/SHM siblings, `Application Support/covers`, and Caches, matching the app's current OP-SQLite and CoverStore locations. No directory is created, deleted, compacted, or read for content.

Both implementations perform file metadata traversal off the UI thread, exclude symbolic links, treat a concurrently removed/missing file as zero bytes, and reject other read failures. JavaScript validates complete safe integer buckets and their sum. Settings displays their sum in decimal MB with one decimal place. Unknown/loading/failed counts leave the title as “数据与备份”; they never display an invented zero. Settings reads actual trash list length, refreshes on focus and related feature events, and refreshes cache size after closing export.
